# 2026-08-04: 新規タブでpixivのリファラエラーが出るバグを修正

## 決定事項とWhy

ユーザーが実機のRoopieでpixivを閲覧中に「pixiv内のリンクからこのページを参照するか、リファラの送信を許可してください」というエラーに遭遇（ホットリンク防止）。コードベースにreferrer/Refererを扱う箇所が元々存在せず（Grep該当0件）、原因を`tab-manager.js`の`setWindowOpenHandler`（`target="_blank"`・Ctrl+クリック・ホイールクリックで新規タブを開く経路）に絞り込んで特定した。

- `wc.setWindowOpenHandler`（旧569行付近）は`details.referrer`（Electronが計算した正しいReferrer）を受け取っていたが、`createTab(details.url, {...})`へ渡さず捨てていた。
- `createTab`内の`view.webContents.loadURL(url)`（旧354行）もreferrerオプション無しで呼んでいたため、新規タブは常にリファラ無しで開いていた。
- pixivの画像を新規タブで開く操作（サムネイルのtarget=_blankリンク、Ctrl+クリック等）はこの経路を通るため、対象サイトを問わず新規タブ全般でリファラが欠落する状態だった。

## 変更内容

`src/main/tab-manager.js`:
1. `createTab`のオプションに`referrer = null`を追加。
2. `loadURL(url)` → `loadURL(url, referrer?.url ? { httpReferrer: referrer } : undefined)`。
3. `setWindowOpenHandler`内の`createTab`呼び出しに`referrer: details.referrer`を追加。

`docs/specs/SPEC-tabs.md`に制約と変更履歴を追記。

## 検証

`npm run start:verify`で第二インスタンスを起動しようと試みたが、ユーザーの実機Roopieが起動中（`requestSingleInstanceLock`）のため既存ウィンドウをフォーカスして即終了し、コンソールログでの確認はできなかった。変更は`details.referrer`（Electron 43の`HandlerDetails.referrer: {url, policy}`）を`loadURL`の`httpReferrer`オプションへそのまま渡すだけの機械的な受け渡しで、既存の分岐・タイミングには影響しない。

## タスク進捗状況

完了。ユーザーには実機のRoopieを再起動して反映することを伝える必要あり（プロセスは変更を検知しない）。

## 次回への引き継ぎ

1. ユーザー報告で再現しなければ、`setWindowOpenHandler`ではなく直接ナビゲーション（アドレスバー入力・通常リンククリックでの遷移）経由でも同じエラーが出ていないか確認する（この経路は今回のリファラ引き継ぎの対象外）。
2. `referrer.policy`がpixiv側の要求（`strict-origin-when-cross-origin`等）と食い違う場合は、`{ httpReferrer: referrer }`ではなくURL文字列だけを渡す形に切り替える必要が出るかもしれない（現状はElectronが計算したポリシーをそのまま尊重する方針）。
