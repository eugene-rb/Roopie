# 2026-07-28: スタート画面のショートカットの個数上限を撤廃 + パネルからページに入れたリンクも表示

## 決定事項とWhy

ユーザー依頼「ページにショートカットを一定数以上追加できないのを無制限にして。また、ブックマークのパネルから各ページのフォルダに追加したリンクもショートカットとして見えるようにして」。

**原因は1つ**: 依頼の2件は同じ場所から出ていた。`newtab.js` の `MAX_QUICK_LINKS = 10` で、`reconcileLayout()` が `list.slice(0, MAX_QUICK_LINKS)` として**レイアウト未登録のショートカットを先頭10件しか拾っていなかった**。ブックマークのパネル/管理画面からページのフォルダへ入れたリンクは、保存も配信(`bookmarks:children`)も正しく行われていて、レンダラーのこのsliceで捨てられていた(実データも `ページ1` の子がちょうど10件で頭打ち)。

- `newtab.js`: `MAX_QUICK_LINKS` を削除。`reconcileLayout()` は `list` を全部拾う。追加メニューの「🔗 ショートカット」の `disabled`(10件で押せなくなる)も削除
- `newtab.js` `loadShortcuts()`: `bookmarks:children` の結果から `type === 'folder'` を除いてから使う。パネルからはページの**中にフォルダも作れる**が、フォルダは `url` を持たないため `shortcutKind()` の `url.startsWith()` が TypeError になりグリッドの描画ごと死ぬ
- 表示しきれない分は `#quick-links` の `overflow-y: auto`(`height: --grid-height`)でそのまま縦スクロールして届く。横スワイプのwheelハンドラは `|deltaX| >= 24 かつ |deltaX| > |deltaY|` のときしか `preventDefault()` しないので縦スクロールを邪魔しない。保存側の上限は `widgets.js` の `MAX_ITEMS = 300`(暴走防止)がそのまま効く
- 検証: `scripts/test-newtab-widgets.js` に4項目追加(15件表示 / パネル追加ぶんの表示 / ページ内フォルダを除く / 最下段までスクロールで到達)。全78項目OK。スタブ `stub-internal-preload.js` に `__setShortcuts(pageId, list)` を追加(ブックマーク側の変更通知まで再現)

**この対応の範囲**: ショートカットになるのは**ページのフォルダ直下**のリンクだけ。ページの中に作ったサブフォルダとその中身はスタート画面には出さない(従来どおり)。→ 直後に上のエントリでアプリフォルダ風のタイルとして出すよう変更。
