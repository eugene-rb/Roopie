# 2026-07-29: タブの見た目設定を3系統(アクティブ / メディア再生中 / タブグループ)に拡張

## 決定事項とWhy

ユーザー依頼「現在の再生中のタブの見た目の設定と同じように、アクティブ・メディア再生中・タブグループのそれぞれに見た目を設定できるようにして」。

**描画先を ::after から専用の子要素へ移した**

- これまでは `[data-audio-effect='x'] .tab.audible::after` の1枚だけで描いていた。`::after` は1要素に1つしか無いので、**3系統を重ねられない**(ニャンキャットは `::before`+`::after` を両方使っており、拡張の余地も無かった)。
- 描画先を `.tab` の子要素 **`.tab-fx`(1系統につき1枚)** に変更。`position:absolute; inset:0; z-index:-1` で、`.tab` の `isolation:isolate` によって「背景より上・文字より下」という元と同じ層に入る。絶対配置なのでフレックスの並び(ニャンキャットの `order`)にも影響しない。
- 各要素は `data-effect`(種類)と `--fx-1` / `--fx-2`(色。レンダラーがインラインで入れる)を持ち、CSSは `.tab-fx[data-effect='...']` だけを見る。**祖先の属性を見なくなったので、設定画面のプレビューでも同じ要素を作るだけで同じ見た目になる**。
- ニャンキャットは1系統で虹と猫の2枚が要るので、`.tab-fx[data-effect='nyan']` の `::before`(虹)/`::after`(猫)を使う。`::after` は `content` を自前で持たせる(元は共通ルールから継いでいた)。
- **移設で落としてはいけなかったもの**: `.tab.split .tab-fx { bottom: 2px }`(分割中の下線が全面塗りに覆われる)/ `--fx-delay` は**タブ側**に置いて全系統で共有(位相を1本の時計に合わせる)/ `:root` の `--audio-fx-1/2` は `.tab-fx` の既定値として残す(未定義だと `color-mix()` ごと無効になり15種中13種が消える)。
- ニャンキャットはタブの中身の配置・縁取りも変えるので、**どの系統で選ばれていても効くよう** renderer.js が `.tab.fx-nyan` を付け、旧 `[data-audio-effect='nyan'] .tab.audible` 起点のルール(場所空け・order・黒縁取り・ホバー時に猫を消す・細いタブのコンテナクエリ)を全部この起点に張り替えた。

**設定**

- `activeTabEffect` / `audioTabEffect`(既存キーのまま) / `groupTabEffect` と、それぞれの色2つ。既定は none / breathe / underline。
- `ipc.js` の `settings:set` の検証を3キーとも通す(末尾の else は無検証で通してしまうため、正規表現で色キーもまとめて拾う)。
- 色が空のときの既定は、アクティブ/再生中=アクセント色、**グループ=そのグループ自身の色**(`var(--group-red)` など)。グループごとに色が違って見えるのが自然なため。色を指定するとそちらが優先。
- 設定画面は3系統ぶんを**同じ作りで組み立てる**(`EFFECT_TARGETS` を回して「選択・色・プレビュー」の3行を生成)。プレビューは本物と同じ `.tab` + `.tab-fx` で作るのでCSSを二重に持たない。

**重なる順**: グループ(地)→ アクティブ → メディア再生中(最前)。DOMの順番がそのまま重なりの順になる。

**検証**: `scripts/test-tab-audio-effect.js` を新方式へ全面更新(`::after` を見ていた箇所を `.tab-fx` に張り替え)+3系統の項目を追加(それぞれの系統が正しいタブにだけ付く/3つ重なったときの順序と種類/グループ色の既定と上書き/「なし」で要素ごと消える)。全項目OK。`scripts/test-tab-ui.js` のプレビュー用プローブも新方式に更新。

**あとから直した2件(レビューで発覚。どちらも検証スクリプトの穴だった)**

- **チップのインライン改名が、再描画のたびに全選択され直して消えていた**。`renderTabs()` はタブの読み込み・メディア状態・設定の変更でも走る(今回 `applyAudioTabEffect` からも呼ぶようにした)ので、入力中に何度でも作り直される。①入力内容だけでなく**カーソル位置**も覚えて戻す(全選択し直すと次の1文字で全部消える)②作り直しの間だけ `rebuildingTabs` を立て、その間の `blur` では確定しない(そうしないと入力途中で勝手に確定する)。**新しいグループを作った直後は必ずこの入力欄が開く**ので、既定の操作でいきなり踏む経路だった。
- **2段目のタブを✕で閉じたとき、幅の固定が1段目に掛かっていた**。`lockTabWidths()` が常に `#tabs` を触っていたため、2段目では✕がカーソルの下から逃げたまま(この機能を作った意味が無い)、かつ1段目が別の幅で1秒固定されていた。閉じたタブの親要素(`#tabs` か `#group-tabs`)を見て、その段だけに掛けるよう修正。CSSも `#group-tabs.width-locked .tab` を追加。
- あわせて、別ウィンドウから2段目に落としたタブも同じウィンドウ内の移動と同じくグループへ入るようにした(以前は落とした段から即座に消えていた)。

**既知の失敗(このセッションの変更とは無関係)**: `scripts/test-media-multi.js` の4項目と `scripts/test-background-tab.js` の1項目は、**このセッションの作業前(コミット 3e4d7f7)でも同じように落ちる**ことを確認済み。

**検証で撮れないもの**: 設定画面のスクショは `Current display surface not available for capture` で撮れないため、3つのプレビューは構造(要素・属性・色)とコンソールエラー0件で確認しており、目視はしていない。
