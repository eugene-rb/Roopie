# 2026-08-04: docs/specs/ を新設し「3層クエリルール」「SPECテンプレート統一」を実行可能化

## 決定事項とWhy

CLAUDE.md（プロジェクト側）が定める「3層クエリルール」（① graph.json → ② Obsidian Vault / `docs/specs/` → ③ 生コード）と「SPECファイル構成統一」テンプレートは、機能マトリクス表が既に9個のSPECファイル名（`SPEC-tabs.md` 等）を参照していたにもかかわらず `docs/specs/` ディレクトリ自体が存在せず、実行不能な状態だった。ユーザーから「3層クエリルールやSPECテンプレート統一などを実行できるようにして」と依頼があり、Plan Modeで計画（影響範囲・対象9ファイル・ロールバック手順）を提示し承認を得たうえで実施した。

- 事前調査はExploreサブエージェントに委託し、`tab-manager.js`(1736行) / `browser.js`(1659行) / `ipc.js`(1276行) など大きいファイルを全文読みせず、IPCチャンネル名・エクスポート・依存関係・コメント中の制約のみを抽出する形でトークンを節約した（CLAUDE.md不変条件2「巨大ファイルは全読みしない」に準拠）。
- `docs/decisions/`（ADR）と `docs/vault/`（Obsidian、`/resume`・`/save` 用）は今回のユーザー依頼の対象外として着手せず、範囲を絞った。
- 併せてユーザーからAivis音声通知（不変条件10）の運用範囲について「確認の時にしゃべって」「ユーザーの操作が可能/必要になったすべての場合」との指示があり、CLAUDE.md不変条件10がその内容に更新された（ユーザーまたはリンタによる直接編集、以後この定義に従う）。

## 作成したファイル

`docs/specs/` 配下に以下9ファイルを新規作成（全て概要/詳細/検証/変更履歴の4節構成テンプレートに準拠）:

- `SPEC-tabs.md` — タブ管理（`tab-manager.js` 他）
- `SPEC-sidebar.md` — サイドバー（`side-panel.js`）
- `SPEC-translate.md` — 翻訳（`translate.js` / `page-translate.js` / preload）
- `SPEC-theme.md` — ウィンドウテーマ（`browser.js` テーマ部分 / `theme.js` / `window-theme.js`）
- `SPEC-extensions.md` — 拡張機能（`extension-support.js`）
- `SPEC-release.md` — リリース/更新（`updater.js` / `.github/workflows/release.yml`）
- `SPEC-permissions.md` — サイト権限（`site-permissions.js`）
- `SPEC-default-browser.md` — 既定ブラウザ（`default-browser-registry.js` / `default-browser.js`）
- `SPEC-profile.md` — プロファイル（`profiles.js`）

CLAUDE.md本体・機能マトリクス表は変更不要（既存の参照名と一致することを確認済み）。

完了。

## 次回への引き継ぎ

1. 今回対象外とした `docs/decisions/`（ADR）と `docs/vault/`（Obsidian Vault、`/resume`・`/save`）は未着手のまま。ユーザーから依頼があれば新設する。
2. SPECファイルの内容はコードサーベイ時点（2026-08-04）のスナップショット。該当ファイルに大きな変更が入った際は該当SPECの「変更履歴」節に追記して更新すること。
3. 機能マトリクスの他項目（タイマー/パスワード/スタート画面/ジェスチャー/広告ブロック/履歴・ブックマーク・ダウンロード）は元々SPEC対象外（マトリクス表で「-」表記）のため今回スコープ外のまま。
