## 発端

依頼は2つ。

1. スタート画面の背景に glassmorphism の選択肢を足す
2. liquidglass テーマのとき、システムタブやパネルもすべて透過させる

2 は前回「`WebContentsView` が transparent ではないので透かすと黒が出る」として
偽ガラス（ページ自身が光を敷き、その上の面をぼかす）を採った箇所。

## 実測（`scripts/test-view-transparency.js`）

`test-window-material.js` と同じく、背後に縞模様のウィンドウを敷いて**画面から**撮る
（`capturePage` は WebContents 自身の絵しか写らず DWM の合成が見えない）。

| 条件 | 結果 |
| --- | --- |
| `transparent:false` + body 透過 | **白**が出る。黒ではないが文字が読めず駄目なのは同じ |
| `transparent:true` + body 透過 | **acrylic が出る**。縞がぼけて透け、カードも文字も読める |
| `transparent:true` + スクリム60% | ほぼ不透明に見える。透過感を出すなら 0〜30% が上限 |

→ 従来の記述は**プラットフォームの限界ではなく View の生成時オプションの話**だった。
オーバーレイ（`browser.js:677`）や分割の仕切り（`tab-manager.js:415`）は現に
`transparent: true` で作られている。ただしその2つが透かしているのは「別のView（実ページ）」で、
「ウィンドウの acrylic」ではない。合成の経路が違うので実測が要った。

## Decisions

- **透明かどうかはCSSだけで決める** → `transparent` は生成時にしか渡せないので、
  内部ページとサイドパネルは**常に**透明なViewで作る。既定のCSSは不透明のままなので、
  土台のコミット単体では見た目が1pxも変わらない（退行ゼロで刻める）
- **通常のWebページとWebパネルには付けない** → 背景を宣言していないサイトが
  白ではなくデスクトップを透かしてしまう
- **既定は完全透過 + `pageScrim` で調整可能**（0〜60%、既定0）。上限60%は実測から
- **`--surface-alpha` には触れない** → 黒画面事故の既知原因。別名 `--page-scrim` にして
  コメントでも「別の仕組み」と明記した
- **アクセント色の光は消さずに減光**（40/22/26% → 22/12/14%）。あれは本物の透過が
  使えないことの代替だったので acrylic の上に元の濃さで重ねると濁る。ただし全部消すと
  liquidglass の色の個性が無くなる
- **スタート画面の `glass` は二重の意味を持たせた** → 普段はページ自身がオーブを描き、
  ウィンドウ外観も liquidglass のときだけ `#bg` を透明にして本物の透過になる。
  「透過だけ」にすると solid のとき単色（＝`plain` と同じ）になって選択肢が壊れる

## 検証でわかったこと（重要）

**liquidglass の透過はスクショでは判定できない。**

- `capturePage()` は WebContents 自身が描いた絵しか写さない。透明領域は透明のまま返るので、
  黒い画像は偽の警報、正常な画像は偽の合格になる
- `gen-screenshots.js` の `desktopCapturer` も駄目だった。この環境では WGC の初期化に失敗して
  （`wgc_capturer_win.cc: Failed to start capture`）BitBlt に落ちており、その状態だと
  **透明な子Viewの中身を取りこぼす**。実際 `01-start` がページ領域まっ黒で撮れた。
  リポジトリにコミット済みの同じ画像には中身が写っているので、これはキャプチャ側の限界。
  レンダリングの不具合ではない（探りでは透明なViewが正しく描画されている）
- 画面全体のキャプチャ（`CopyFromScreen`）に切り替える案は**撤回した**。他ウィンドウが重なると
  無関係な画面を撮ってしまい、実際にユーザーの別ウィンドウが写った（撮れた一時ファイルは削除済み）。
  探りスクリプトのように `alwaysOnTop` で自分のウィンドウだけを最前面に固定できる場面でしか使えない

→ **実機の目視が必要**。`gen-screenshots.js` は今回変更していない。
