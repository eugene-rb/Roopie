# 2026-07-25: 裏タブを「読み込むが再生させない」方式(media-guard)へ

## 決定事項とWhy

ユーザー依頼「読み込むかつ再生しない、一時停止とは違う方法はない?」への対応。

**動機**: 直前までの保護は「裏タブはそもそも読み込まない」(`hibernated`)1本で、音は確実に止まるが**タブを選ぶたびに読み込み待ちが出る**。読み込みは済ませたうえで、再生が始まる経路だけを塞ぐ形に変えた。

**採用しなかった案と理由**:
- `webPreferences.autoplayPolicy: 'document-user-activation-required'` … 過去の実測どおり、メインプロセスの `loadURL()` 由来の遷移では実サイト(http/https)に効かない。仮に効いてもドキュメント単位なので自分で押した再読み込みまで巻き添えにする。`executeJavaScript(code, true)` で後から user activation を与える手も、そもそも塞げていないので無意味
- `autoPauseMedia`(鳴った瞬間にpause) … 「一時停止とは違う方法」という依頼そのものに反する

**実装**:
- `src/preload/media-guard-preload.js`(新規、`registerPagePreloads` でセッション全体に登録)。分離ワールドからは `HTMLMediaElement.prototype` に触れないので、`webFrame.executeJavaScript` でメインワールドへガードを入れる(ページのスクリプトより先)。
  - `play()` を **`NotAllowedError` で拒否**(Chromeが自動再生を止めたときと同じ例外なので、サイトは「大きな再生ボタンを出す」など想定済みの経路に落ちる)
  - `autoplay` 属性/プロパティを外す(`<video autoplay>` は `play()` を呼ばずに鳴り出すため)。`document` を見張る MutationObserver + プロパティ記述子の差し替えで、パース途中に現れる要素も拾う。ページから見た `el.autoplay` は true のまま返す
  - `pause()` は一切呼ばない = **一度も再生されない**(検証で `currentTime === 0` を確認)
- 対象判定は preload からの**同期IPC** `media-guard:blocked`(非同期だとページのスクリプトが先に `play()` を呼んでしまう)。メイン側の台帳は `src/main/media-guard.js` の WeakSet(タブを閉じたときの後始末が要らない)
- 解除は `TabManager#switchTab` → `mediaGuard.release(wc)` → 全フレームへ `__roopieMediaGuard.release()`。塞いでいた要素はここで初めて再生される
- **`nodeIntegrationInSubFrames: true`(通常ページのみ)**: preloadは既定だとメインフレームでしか走らず、iframeに置かれたプレイヤー(広告など)を取りこぼすため。sandbox + contextIsolation は維持しているのでページ側からpreloadは見えない
- `createTab` に `hibernate` オプションを新設。**セッション復元だけは従来どおり読み込まない**(起動時に数十タブを一斉に読み込むのは重い。Chrome/Edgeも復元タブは遅延読み込み)。タイマーの「タブを休止する」も同じ `hibernated` を使い続ける

**検証**: `scripts/test-autoplay-policy.js` を全面書き直し(25項目)。script側の `play()` / `autoplay` 属性 / iframe内 の3経路すべてが裏タブで塞がれ、切り替えると全部鳴り出すこと、前面タブとF5再読み込みは素通しであること、解除済みタブを再読み込みしても塞ぎ直さないことを確認。`test-background-tab.js` は新挙動へ更新(`hibernate: true` の経路も残して検証)。`test-restore-autoplay.js` は復元=hibernate のまま無変更で通る。
