# 2026-07-26: 全画面表示をすべてのサイトで許可制に

## 決定事項とWhy

ユーザー依頼「フルスクリーンをすべてのサイトで許可制にして」。ユーザー判断: **許可だけ記憶・ブロックは今回限り** / **設定画面の管理UIを入れる**。

**変更前** — `tab-manager.js` にハードコードした許可リスト(YouTube/Netflix/NHK等 約35サイト)だけを無条件で許可し、他は問答無用で拒否していた。ユーザーが自分で許可を足す手段が無かった。

**設計判断: 許可を「後から」返せるか**

- 権限は `session.setPermissionRequestHandler` の `fullscreen` で受ける。確認バーを出す以上、`callback` を数秒後に呼ぶことになるが、**遅らせても全画面に入れるか**が設計の前提だったので、先に使い捨てスクリプトで実測(3秒後に許可 → `requestFullscreen()` は `ok`、`htmlFullscreenTabId` も立つ)。Electron は `EnterFullscreenModeForTab` から権限を非同期に問い合わせ、返ってきてから全画面へ入るため問題ない。
- 判定は**要求の時点**で行う方針は据え置き(後から `exitFullscreen()` で戻すと一瞬全画面になり、ページ側の状態も残る)。

**実装**

- `applyFullscreenPolicy(session, decide)` に変更。判定を `decide(wc, url)` へ委ね、`tab-manager.js` からウィンドウ・設定の知識を追い出した(検証ではスタブを差せる)。`FULLSCREEN_ALLOWLIST`/`isFullscreenAllowed` は削除。
- 新規 `src/main/site-permissions.js`(純関数): `hostFor`(http/https以外は null = 尋ねずに拒否)、`isGranted`、`addHost`、`normalizeHosts`。**判定はホスト名の完全一致**(Chrome同様オリジン単位)。末尾一致にすると `youtube.com.evil.net` を通すため。サブドメインは別サイトとして改めて尋ねる。
- `browser.requestFullscreenPermission(wc, url)`: 許可済みなら即 true。**見えていないタブ(アクティブでも分割相手でもない)からの要求は尋ねずに拒否**。確認バーを出して返事を待ち、ページ移動・タブ破棄・ウィンドウclose・60秒で取り下げる(未解決の callback を残さない)。
- `browser.respondFullscreenPrompt(ctx, allow)`: **返事の時点でもう一度「そのタブが見えているか」を確認**してから許可する(返事を待つ間にタブを切り替えていると、見ていないサイトへ許可を与えてしまう)。
- 保存は `fullscreenAllowedSites` 設定(プロファイル別)。**シークレットの許可はディスクへ書かず、メモリ(profileId → Set)に持つだけ**。
- `TabManager` に `isFullscreenGranted` を渡し、`enter-html-full-screen` の保険判定を許可リストと同じ判定に差し替え(権限を通らずに全画面へ入る経路が残っていた場合の防波堤)。
- UI: ツールバー下の確認バー `#fullscreen-bar`(パスワード保存バーと同型)。設定画面に「サイトの権限 > 全画面表示」を新設(許可済み一覧・個別取り消し・すべて取り消す)。

**検証** — 新規 `scripts/test-fullscreen-permission.js`(28項目、実UI)

- 確認バーの表示 → 実クリックで「許可」→ 記憶 → 二度目は尋ねない / 「ブロック」は記憶せず次もまた尋ねる / 裏のタブは尋ねずに拒否 / ページ移動で取り下げ / シークレットの許可は保存しない・通常ウィンドウへ持ち込まない / 設定画面から取り消せる。
- 最後にページ自身の `requestFullscreen()` からの通しも確認(バー → 「許可」→ 実際に全画面)。
- 既存 `scripts/test-fullscreen.js` は新APIへ更新。**削除した「サブドメインも許可」の代わりに「サブドメインは別サイト扱い」を入れ、偽装ドメインを弾く2件はそのまま残した**。
- 注意: この環境では `requestFullscreen()` の解決と `exitFullscreen()` を待つ3〜4項目が**変更前(HEAD)から落ちる**(worktreeで基準を取って確認済み。GPU/OSの全画面遷移待ちの問題で、今回の変更とは無関係)。

**挙動の変化** — YouTube等これまで無条件で全画面にできたサイトも、最初の1回だけ確認バーが出る(依頼どおり)。
