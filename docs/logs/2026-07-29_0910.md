# 2026-07-29: タブのグループ化と二段タブバー

## 決定事項とWhy

ユーザー依頼「タブのグループ化(手動と、タブバーの右クリックメニューからドメインごとに自動仕分け)と、二段タブバー(タブグループを選択した際、二段目にグループの中身を表示。グループ化されていないタブを選択した際は二段目なし)」。

**確認した仕様(ユーザー選択)**: 縦タブは2段目の代わりに折りたたみサブリスト / グループはタブ復元と一緒に再起動後も復元 / 自動仕分けは `google.com` 単位(サブドメインはまとめる)・1件だけのドメインはグループにしない。

**データの持ち方**

- グループは**ウィンドウ単位**(`TabManager#groups` = `{ id, name, color }` の配列)。所属は**タブ側の `tab.groupId`** が持ち、グループ側はタブIDを持たない(生成・移動・破棄の全経路で двух側を同期させるのは事故のもとなので、一覧が要るところは `tabs` から引く = `tabsInGroup()`)。
- 中身が空になったグループは `pruneEmptyGroups()` で消す(`closeTab` / `releaseTab` / 所属変更のたびに呼ぶ)。
- `gatherGroup()` でメンバーをタブの並びの上で連続させる(1段目のチップの位置が飛ばないように)。
- 別ウィンドウへ移すとき(`releaseTab`)は `tab.groupId = null`。グループIDはウィンドウ内の採番なので移動先では意味を持たない。
- リンクから開いたタブ(`openerTabId` あり)は**リンク元のグループを継ぐ**(Chromeと同じ)。ショートカットや「+」で開いたタブはグループ外。

**二段タブバー**

- 1段目(`#tabs`)= グループ外のタブ + グループ1つにつきチップ1枚(`.tab-group-chip`。色の丸・名前・件数)。チップはそのグループの**先頭メンバーの位置**に出す。
- 2段目(`#group-row`)= **選択中のタブが属するグループ**の中身。出す条件は `activeTab.groupId` から毎回導く(別途「選択中のグループ」状態を持たない=ズレようがない)。
- 段の高さの変化は既存の `#chrome` の ResizeObserver → `ui:chrome-height` でメインへ伝わり、ページ表示領域が自動で追従する(追加の配線は不要だった)。
- 縦タブ(`vertical-tabs`)は2段目を使わず、選択中のグループの中身をチップの直後に字下げして出す(`.tab.in-group-list`、左端にグループ色の帯)。

**操作**

- タブの右クリック: 「タブをグループに追加 > 新しいグループを作成/既存のグループ」「グループ『名前』から外す」「ドメインごとに自動でグループ化」。
- チップ: クリック=**そのグループで最後に見ていたタブ**へ移る(`recentTabIds` を再利用。無ければ先頭)、ダブルクリック=インライン改名、右クリック=新しいタブ/名前を変更/色(9色)/グループを解除/中身をすべて閉じる。
- 改名はメインプロセス側にテキスト入力の手段が無いので、メニューからは `tab-group:rename-request` をタブバーへ送って**インライン編集を開く**方式にした。
- **ドラッグ&ドロップ**: 2段目に落とす=そのグループへ入る / 1段目に落とす=グループから外れる(1段目にはグループの内側を指す位置が無いため、この対応で迷いが出ない)。`attachDropTarget(barEl, container)` で1段目と2段目に同じ受け口を張り、スロット表示・端の自動スクロールも「今狙っている段」(`dropContainer`)の中だけで行う。
- **段の中の位置 → タブ全体の並びの位置**の変換が要になる(`flatDropIndex()`)。1段目はチップが混ざり、2段目は中身だけなので、見えている位置をそのまま `moveTab` に渡すと**まったく別の場所に入る**。チップに落としたときはそのグループの先頭タブの位置、2段目の末尾はそのグループの最後のタブの次、と読み替える。

**自動仕分け(`groupByDomain`)**

- `src/main/tab-groups.js`(純関数)に `registrableDomain()` と `planDomainGroups()` を分離。PSLを丸ごと持つのは重いので、**ccTLD(2文字)+ よくある2階層目(co/ne/or/ac/go/com/net/org...)のときだけ3ラベル**取るヒューリスティック(`www.asahi.co.jp` → `asahi.co.jp`)。http/https 以外は対象外(内部ページ・file: はグループにしない)。
- 既にグループへ入れてあるタブは動かさない(手で作ったグループを壊さない)。同名グループが既にあればそこへ足すので、2回実行してもグループは増えない。

**復元**

- `snapshotTabs()` の各エントリに `group: { key, name, color }` を**丸ごと埋める**。呼び出し側(`browser.js` の起動時復元・閉じたウィンドウの復元)は `tabs` 配列しか受け渡ししておらず、別配列を足すと全経路の引数を変えることになるため。`restoreTabs()` は key ごとにグループを作り直す。

**検証**: 新規 `scripts/test-tab-groups.js`(33項目)。ドメイン判定の純関数、グループのCRUD・連続配置・空グループの掃除・自動仕分けの冪等性、1段目/2段目の出し分け、チップで最後に見ていたタブへ戻ること、縦タブの折りたたみ、復元後もグループが戻ること。ネットワーク不要にするため、URLを持つタブは `createTab(url, { background: true, hibernate: true })` で**読み込ませずに**作る(`tabUrl()` が `hibernatedUrl` を返すのでドメイン判定はできる)。

**やっていないこと**: グループのチップ自体をドラッグしてグループごと並べ替えること(今回はタブ単位の移動のみ)。
