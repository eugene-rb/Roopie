# 2026-07-29: 権限の確認をカメラ・マイク・現在地・通知へ広げ、「今回だけ許可」を追加

## 決定事項とWhy

ユーザー依頼「カメラ・マイク・位置情報・通知にも対応して。また、選択肢に今回だけ許可を追加して」。

**先に実測したこと(設計の分かれ目)** — `scripts` には残していない探索用スクリプトで確認:

- `setPermissionCheckHandler` が false を返しても `setPermissionRequestHandler` は呼ばれる(=checkで塞いでも都度確認はできる)。
- ただし check が false だと `permissions.query({name:'notifications'})` と `Notification.permission` が **denied** を返す。Chrome の `prompt`/`default` に当たる状態を boolean では表せず、サイトが「通知はブロックされています」と判断して `requestPermission()` を呼ばなくなる=**確認そのものが出なくなる**。→ **check ハンドラは入れない**(未許可のサイトからは `query()` が granted に見えるが、実際の可否は request ハンドラが握っている)。
- **Chromium 側は権限を一切覚えない**: 同じページで2回 `getUserMedia` を呼ぶと request も2回来る。ページ遷移後も来る。記憶はすべてこちらの責任。
- media の `details.mediaTypes` は**入らないことがある**(この実機ではマイクが無く、`{audio:true,video:true}` は request すら来ずに NotFoundError)。→ 空で届いた要求は**カメラ・マイクの両方**として尋ねる(空を「尋ねない」に倒すと黙って許可することになる)。

**実装**

- `src/main/site-permissions.js` を汎用化。`KINDS`(camera / microphone / geolocation / notifications / fullscreen)・`LABELS`・`kindsFor(permission, details, {ask})`(Electronの permission 名 → 独自の種類)・`isGranted(grants, kind, url)`・`addGrant()`・`normalizeGrants()`・`migrateSettings()`。
- `tab-manager.js` の `applyFullscreenPolicy` → **`applyPermissionPolicy(session, decide)`**。全権限を `decide()` に渡し、`decide` が扱わないもの(clipboard-read・midi・speaker-selection 等)は従来どおり `callback(true)`。
- `browser.js` に `requestSitePermission(wc, permission, details)`。**決まっていない種類だけを集めて**1回のポップアップで尋ねる(カメラ許可済みならマイクだけ尋ねる)。返事は `'always' | 'once' | 'block'` の3値。
- **「今回だけ許可」**: `tempGrants`(wc.id → `{topHost, keys}`)。**サイトを離れた時点で捨てる**=`did-start-navigation` でトップのホストが変わったら丸ごと削除。判定時に今のホストと比べるだけの実装(見張り無し)も試したが、**別サイトへ行って戻ってくると生き返る**のを検証で踏んだため見張りを入れた。同じサイト内のページ移動では残す(Chrome の「今回のみ許可」と同じ)。このリスナは wc とこのMapしか触らないので、タブをウィンドウ間で移しても張り直しは不要(`tab.wcListeners` の作法の対象外)。
- **順番待ち**: 同時に来た要求は ctx ごとの Promise チェーンで1つずつ出す(従来は2件目を黙って拒否していた)。上限3件、あふれたら警告を出して拒否。
- 保存形式は `settings.sitePermissions = { camera: [...], ... }`。旧 `fullscreenAllowedSites` は `bundleFor` で1回だけ畳んで**旧キーを消す**(冪等。あとで取り消したホストが次の起動で復活しない)。`ipc.js` の `settings:set` にも `sitePermissions` の検証分岐を追加(既定の else は無検証で通るため)。
- **シークレットの許可はプロファイルではなく「そのウィンドウのセッション」に紐づける**(`WeakMap<session, {kind:Set}>`)。シークレットのセッションはウィンドウごとに作られ閉じると消えるので、次に開いたシークレットウィンドウへ許可が残らない。プロファイル単位のMapのままだと、閉じても消えず**次のシークレットがカメラ許可済みで始まる**(全画面表示だけの頃から在った作りだが、カメラ・マイク・現在地に広げると実害になる)。判定・付与の引数は `{ profileId, incognito, session }`(=ウィンドウの文脈 ctx をそのまま渡せる形)に揃えた。
- **注意(今は無害)**: `store(profile, 'settings', { ...DEFAULT_SETTINGS })` は浅いコピーなので、settings.json がまだ無いプロファイル同士は**同じ `sitePermissions` オブジェクト(と中の配列)を共有する**。現状は `addGrant` → `normalizeGrants` が必ず新しい配列を作るので事故らないが、`data.sitePermissions.camera.push(host)` のような破壊的更新を足すと全プロファイルへ許可が漏れる。
- UI: `#perm-popup` に求められている権限を**行で並べ**(カメラ+マイクのように複数来る)、ボタンは3つを**縦積み**(横並びだと「今回だけ許可」が窮屈)。設定画面「サイトの権限」は5種類ぶんを1つの描画関数で回す(`#permission-kinds .perm-kind[data-kind=...]`)。

**検証**: `scripts/test-fullscreen-permission.js` を **`scripts/test-site-permissions.js` へ改名して拡張(102項目OK)**。**カメラだけはページからの通しも入れた**(`getUserMedia` → ポップアップ → 数秒待たせてから「許可」→ `'ok'`)。要求を保留している間にデバイスの取得が落ちないことは、ハンドラを直接呼ぶ経路では確かめられないため。マイクはこの実機に無いので直接呼ぶ経路のみ(カメラの有無は `enumerateDevices` で見て、無い環境では通しを飛ばす)。ドロップダウンの既存項目は全部残したうえで、種類ごとの独立・2種類同時・`mediaTypes` 欠落・「今回だけ許可」の非保存/同一サイト継続/別サイトで失効・順番待ち・移行の冪等性・設定画面の種類別取り消しを追加。ページからの通しは**通知と現在地**で行う(カメラ・マイクは実機のデバイス構成に左右されるためハンドラを直接呼ぶ)。`test-fullscreen.js` も新APIへ更新。

**検証で踏んだ罠**: ポップアップの中身(`#perm-items`)は閉じても残るので、`items` だけを比べると**前の要求の残骸を掴んで通ってしまう**。`checkPrompt()` で「出ている(hidden でない)」ことと中身を必ず一緒に見る。
