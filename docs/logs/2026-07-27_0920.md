# 2026-07-27: Googleログイン等の window.open をポップアップウィンドウで開く(Edge/Chrome相当)

## 決定事項とWhy

ユーザー依頼「edgeなどと同じようにgoogleでログインなどを使うときにポップアップウィンドウを出すように」。

**なぜタブではだめか**: 従来 `setWindowOpenHandler` は全部 `action:'deny'` + `createTab` にしていた。denyすると `window.opener` の縁が切れるため、OAuth(認証ページが `window.opener.postMessage()` で結果を返して自分で `window.close()` する)が完了しない。`action:'allow'` で本物の子ウィンドウを開くしかない。

**判定**: 実測(`scripts/test-popup-window.js` の調査時)で、`window.open(url, name, 'width=500,height=600')` も `popup=yes` も `disposition: 'new-window'`、features無しの `window.open`/target=_blank は `'foreground-tab'`。ただしShift+クリックも `'new-window'` で来る(featuresは空)ため、**disposition が new-window かつ features にウィンドウの形の指定(width/height/left/top/screenX/screenY/innerWidth/innerHeight/popup)がある**ものだけをポップアップにした。Shift+クリックは今までどおりタブ。

- 新規 `src/main/popup-window.js`
  - `isPopupRequest(details)` … 上の判定。`responseFor(details, ownerWindow)` … `{action:'allow', outlivesOpener:true, overrideBrowserWindowOptions}` を返す
  - `webPreferences` は**渡さない**。セッション・preload・sandboxは開いた側から引き継がれる(`partition` を書くと別セッションになりログイン中のCookieが渡らない / `preload` を渡すと内部APIが通常のWebページから見える)
  - features の大きさ・位置は開いた側のモニタの作業領域に収める。`useContentSize:true`(ページ指定は中身の大きさ)
  - `outlivesOpener:true` … 開いた側のタブを閉じてもポップアップは残る(Chrome/Edgeと同じ)
  - `setup(win, details, tabManager)` … `win.setMenu(null)`(Windowsではアプリメニューが全ウィンドウに出るため。ショートカットもこのウィンドウでは効かなくなる)、右クリックメニューを付ける、ポップアップ内のリンクは親ウィンドウのタブへ、ポップアップからのサイズ指定付き window.open はさらにポップアップ、`roopie://` への遷移は親のタブへ回す(ポップアップは内部preloadを持たない)
  - どのウィンドウから開かれたかを `owners` に控え、`ownerWindowFor(wc)` で引けるようにした
  - **シークレットだけは例外**で、親ウィンドウの `close` でポップアップも閉じる。`browser.js` は最後のシークレットウィンドウが閉じた時点で `session.clearStorageData()` するが、ポップアップは `windows.all()` に載らないため、残すと「消えたはずのセッション」の上でポップアップだけが生き残る(Chrome/Edgeも最後のシークレットウィンドウを閉じるとポップアップごと閉じる)
- `tab-manager.js` / `side-panel.js`: `setWindowOpenHandler` の先頭で `isPopupRequest` を見る。`did-create-window` で `popupWindow.setup()`。tab-manager側は既存の `on()` ヘルパ経由で張る(タブを別ウィンドウへ移すとき `detachEvents` で外れるように)
- `windows.js` `contextFor()`: ポップアップのwebContentsは開いた側のウィンドウの文脈として返す(右クリックメニューが正しいプロファイルの束を引けるように。循環参照になるので遅延require)
- 検証 `scripts/test-popup-window.js`(24項目 全OK)。素のTabManagerと実際の `browser.createWindow()` の両方で確認。opener への postMessage の往復・自分で `window.close()`・同じセッション・内部preloadが無いこと・features のサイズ/位置・タブが増えないこと・features無しは従来どおりタブ、まで見る。`--online` を付けると実物の accounts.google.com がポップアップで開いて描画されるところまで確認する(ネットワークが要るので既定では走らない)

**やらなかったこと**: Edgeのポップアップにある読み取り専用のアドレスバー(オリジン+鍵アイコン)は未実装。素のネイティブ枠のみ。
