# 2026-07-29: サイトの権限の確認をEdge風のドロップダウンに

## 決定事項とWhy

ユーザー依頼「許可を確認する画面はドロップダウン(edge風)にして」。

**元の状態**: 全画面表示の許可はツールバー下の確認バー `#fullscreen-bar`(パスワード保存バーと同型)で尋ねていた。バーなのでページ表示領域を押し下げる。

**変更後**: オーバーレイ(`roopie://menu`)の `#perm-popup` に、アドレスバーのサイト情報アイコン(`#address-icon`)の真下・左端合わせでぶら下げる。ページに重なるので表示領域は動かない。

- **なぜオーバーレイに描くか**: タブはネイティブView(WebContentsView)なので、クロームUI(index.html)のDOMではページの上に重ねられない。QRポップアップ・プロファイルメニューと同じ理由で、既存のオーバーレイの仕組みをそのまま使う。
- **経路**: メインは今までどおり `fullscreen:prompt { host, what }` をツールバーへ送る → ツールバーは**アンカー(サイト情報アイコン)の位置を測って** `menu:open-permission` で返す → `ipc.js` が `showOverlay(true)` + オーバーレイへ `perm:show`。アンカーの位置はクロームUIしか知らないので、この往復は必要。
- **返事**: オーバーレイから `fullscreen:respond`。`windows.contextFor()` はオーバーレイのwebContentsもそのウィンドウへ解決するため、メイン側のハンドラは変更不要。
- **取り下げ(`settle`)はクロームUIを経由せず、オーバーレイへ直接 `perm:close`**。メインが `showOverlay(false)` まで決めると、同時に開いている別のポップアップ(プロファイル/拡張/QR)を巻き添えで消してしまうため、畳むかどうかは他の表示状態を知っているオーバーレイ側が決める。
- **レース対策**: アンカーを測って戻ってくるまでの間に取り下げられていることがある。`menu:open-permission` は `browser.hasPendingPermission(ctx)` を確かめてから出す(返事の相手がいない空のポップアップを残さない)。
- **UIを消す経路は必ず返事を返す**: この確認だけはユーザー起点ではなく、メインが `pendingFullscreen` にページを待たせている。UIだけ消えると60秒のタイムアウトまでページが止まる。`closePermission(allow)` に集約し、**外側クリック・Escape・ほかのメニューに置き換わったとき**もすべて `false`(ブロック)で返す。
- `position()` に `align` を追加(メニュー類は従来どおりボタンの右端合わせ、権限はEdgeと同じ左端合わせ)。アンカーは拡張機能メニューと同じく `chromeLeft` を引いてオーバーレイ座標へ直す(縦タブ時にずれるため)。
- **実測して確認したこと**: `showOverlay(true)` は `overlay.webContents.focus()` を呼ぶ = バーの頃と違い**ページからフォーカスが外れる**が、数秒後に許可しても `requestFullscreen()` は成功し全画面に入る(通しの項目で確認)。
- **既知の制限**: `isVisibleTabWebContents` は画面分割の相方タブからの要求も受け付けるため、非アクティブ側のペインが要求すると「アドレスバーに出ているのとは別のサイト」の確認がアドレスバーの下にぶら下がる。ポップアップ本文に要求元のホスト名を出しているので取り違えは起きないが、バーだった頃には無かった見え方(Edge流のアンカーが「アドレスバーのサイト」を連想させる)。
- **やっていないこと**: カメラ・マイク・位置情報・通知は今までどおり無条件許可(`setPermissionRequestHandler` の `callback(true)`)。今回は「尋ね方」の変更だけで、尋ねる対象は増やしていない。

**検証**: `scripts/test-fullscreen-permission.js` を新UIへ全面更新(57項目OK)。**縦タブ(`tabBarPosition: 'left'`)のケースを必ず入れる**=横タブでは `chromeLeft === 0` なので、補正が抜けていても位置の検証が通ってしまう(実際に補正を外すと縦タブの項目だけが `popup:387 / icon:387` で落ちることを確認した)。オーバーレイの `#perm-popup` を `getBoundingClientRect()`/`getComputedStyle()` で実測し、幅320px・背景/角丸/影・サイト情報アイコンの直下に出ることまで見る。**返事の検証には `answered()` を挟む**: 60秒タイムアウトの自動拒否も `false` を返すので、素直に `await` すると「返事を返さない不具合」を素通りしてしまう(操作の直後に返ったことまで確かめる)。`test-extensions-menu.js` にリグレッションなし。

**触ったファイル**: `menu.html` / `menu.js` / `internal-preload.js` / `preload.js` / `ipc.js` / `browser.js` / `renderer.js` / `index.html` / `tailwind.css`(+ `npm run build:css`)。
