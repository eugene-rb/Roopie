# DNS-over-HTTPSによる直接接続

ユーザー依頼: 85xo.com / 85po.com / 85po.net をVPN・Torなしで閲覧したい。同階層の `dwnloader` を参考にする。

`Dwnloader.Core/Core/DohResolver.cs` は `https://1.1.1.1/dns-query` へ問い合わせる。通常のDNSでは `www.85po.com` / `www.85po.net` が同じ別IPを返す一方、DoHではCloudflareの配信IPが返った。IP・地域制限と決めつけず、まずDNSの相違を解消する。

Roopieでは `browser.initData()` でElectron標準の `app.configureHostResolver` を設定。ready後、プロファイルセッション生成前に適用する。全プロファイルのChromium通信が対象。サイトへの接続は直接のまま、VPN・Tor・ローカルプロキシや固定IPへの置換は追加しない。証明書検証も変更しない。

- 問い合わせ先はIPリテラルを使い、問い合わせ先自身の名前解決を通常DNSへ依存させない。
- `automatic` では初回の転送先が通常DNSへ戻って失敗したため、`secure` を既定とする。
- DoHが遮断される環境や社内DNS専用の名前を使う場合は、起動時に `ROOPIE_SYSTEM_DNS=1` で従来のOSのDNSに戻せる。OS全体のDNS設定は変更しない。
- `85xo.com` と `www.85xo.com` は公開DoHでもNXDOMAIN。復旧したとは扱わず、別ドメインへの自動転送も追加しない。

## 検証

- 再利用可能な `scripts/test-site-connectivity.js` を追加。一時プロファイル・広告ブロック有効の実タブでDNS、接続経路、HTTPステータス、本文の有無を確認。本文・Cookie・画像は出力しない。任意URLと `--system-dns` を受け付け、localhostの接続も検証する。
- 試行時: `85po.net` → `www.85po.net/ja/` は200・本文あり・DIRECT。
- secure設定の試行時: `www.85po.com` → `www.85po.com/ja/` は200・本文あり・DIRECT。
- 対象サイトをまとめた最終再検証のElectron起動は自動承認レビューが「blocked by policy」で拒否。具体的理由は提示されなかった。この操作は中止し、最終設定での対象サイト全件再検証は未完了。
- 最終実装で `npx electron scripts/test-site-connectivity.js`: example.com、localhostとも200・DIRECT。
- `ROOPIE_SYSTEM_DNS=1` でも同じ一般サイト・localhostの検証に成功。
- `npm run start:verify -- --user-data-dir=<一時ディレクトリ>`: 通常起動のログにレンダラーエラー・未捕捉例外なし。接続テストの終了時にはGPU破棄に伴うログあり。
