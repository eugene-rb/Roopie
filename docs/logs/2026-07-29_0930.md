# 2026-07-29: ウィンドウを閉じたときの復元を「丸ごとそのまま」に

## 決定事項とWhy

ユーザー依頼「ウィンドウ自体を×で消したときは、ウィンドウの中身全部を丸ごとそのまま復元できるようにしたい」。

**元の状態**: ウィンドウ単位の復元(Ctrl+Shift+T)自体は既にあり、位置・大きさ・最大化・タブのURL/タイトル/favicon/アクティブ(+今回追加したグループ)は戻っていた。**戻っていなかったのは「戻る/進むの履歴・ズーム・ミュート・画面分割」**で、開き直したタブは「そのページから始まる新しいタブ」になっていた。

**追加したもの(`snapshotTabs()` の各タブに埋める)**

- `history`: Chromium の NavigationEntry(`{ url, title, pageState }`)一式と現在位置。**`pageState` にはスクロール位置やフォームの入力状態まで入っている**。
- `zoom` / `muted`: そのタブのズーム倍率とミュート状態。
- `split`: 画面分割中なら `{ role: 'main' | 'partner', direction, ratio }`。両方そろっているときだけ組み直す。
- 例によって**タブの配列だけで復元できる形**にしてある(呼び出し側は `tabs` 配列しか受け渡ししていないため)。

**復元のしかた**

- 復元タブは今までどおり**休止(読み込まない)**のまま作る。ただし選ばれた時点(`switchTab` の休止解除)で `loadURL()` ではなく **`navigationHistory.restore({ index, entries })`** を呼ぶ。URLで開き直すと履歴が消えて「戻れないタブ」になるため。
- ズーム・ミュートはタブ生成の直後に入れる(以後の遷移でも保たれる)。
- 閉じたタブ1枚を戻す `Ctrl+Shift+T`(`rememberClosedTab` / `reopenClosedTab`)にも同じ履歴・ズーム・ミュートを持たせた。
- 画面分割は `splitWith()`(「今アクティブなタブと並べる」)ではなく状態を直に組む。

**サイズの歯止め**: 履歴は直近25件まで。1タブぶんが約120KBを超えたら、`pageState` は**今見ているページのぶんだけ残して他は捨てる**(URLと履歴の並びは保つ)。ページによっては `pageState` が極端に大きくなり、`session-tabs` の保存が膨らむため。

**Electron 43 で確認したこと**(使い捨てのプローブで実測): `navigationHistory.getAllEntries()` は `{url, title, pageState}` を返し、`restore()` は**別のウィンドウ/別のwebContentsに対しても効く**(URL・戻れること・件数まで再現)。ただし復元直後のスクロール位置は戻らなかった(`pageState` は遷移時点のものが入るため。実ページで時間が経っていれば入ることもある)。

**検証**: 新規 `scripts/test-window-restore.js`(24項目)。履歴3ページ+ズーム1.5のタブ、ミュート+履歴2件のタブ、グループ、縦分割を作ったウィンドウを×で閉じ、戻したあとに全部が一致すること・**選んでいないタブは休止のまま**であること・休止中のタブを選ぶとそこで履歴ごと復元されること・閉じたタブ1枚でも履歴が戻ることを確認。

**レビューで直した3件**

- **分割の相方のペインが空だった**: 復元直後は誰も選んでいないので相方は休止のまま。しかし画面には出るので**空のペイン**になり、しかもそのタブをクリックすると `switchTab` の「分割相手を選んだら分割を解除する」に当たって分割ごと消えるため、中身を出す手段が無かった。`splitTabId` を立てる**前**に一度 `switchTab(相方)` して読み込ませる(立てた後だと上の解除に引っかかる)。
- **履歴の切り出しが末尾固定だった**: 直近25件を取ると、履歴を戻った状態(例: 40件中5件目)で閉じたときに**今見ていたページが窓から外れ、別のページで復元される**。窓は「今いる位置」を中心に取るよう変更。
- **外部ページのタブの履歴から `roopie://` を落とすようにした**: 復元先タブのpreloadは「今いるページ」のURLで決まるため、外部ページのタブの履歴に内部ページが混ざっていると、戻ったときに `roopieInternal` の無い=何も動かないスタート画面が出る(履歴の底は大抵 `roopie://newtab` なので、今回の変更で初めて到達可能になった経路)。

**やっていないこと**: 閉じたウィンドウの履歴をディスクに残すこと(アプリを終了すると消えるので、最後の1枚を閉じてアプリごと終わった場合は「起動時に前回のタブを復元する」設定が担当する。その経路も同じスナップショットを使うので、今回の追加ぶんはそのまま効く)。

**注意**: `pageState` にはフォームの入力状態も入るため、`session-tabs`(通常プロファイルのみ・シークレットは記録しない)の保存内容がその分だけ広がる。検証は `data:` URLで行っており、実サイト(http/https)での `navigationHistory.restore()` は未確認。
