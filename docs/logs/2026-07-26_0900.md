# 2026-07-26: スタート画面のページ切り替え修正+ページ名 / リンクから開いたタブの位置

## 決定事項とWhy

ユーザー依頼2件(「スタート画面でページの切り替えがうまくいかない。各ページに名前を付けて表示して」「ホイールクリックで開くタブもアクティブタブの右に」)。

**① ページを切り替えるとショートカットが消えたままになるバグ**

- 原因は `switchToPage()` のフェードアウトが `fill: 'forwards'` のまま放置されていたこと。フェードイン側は fill 無しなので、160ms後にフェードインの効果が切れると**合成順で生き残っているフェードアウトの終了状態(opacity 0 / translateX)が再び適用され**、切り替えるたびにグリッドが透明のまま固まっていた。ドット・アイテム数は正しく更新されるので「切り替わらない」ように見える。
- 既存テストは「アイテム数」「activeドット」しか見ておらず素通ししていた。まず `#quick-links` の computed opacity/transform を見る検証を足して**失敗を再現してから**直した。
- 修正: フェードイン開始時に `leave.cancel()`。加えて **最終状態をアニメーションの完走に依存させない**。裏タブなど描画が進まない状況ではアニメーションが `playState: 'running'` / `currentTime: 0` のまま固まり、開始キーフレーム(=透明)を適用し続けるため、`finally` で leave/enter とも `cancel()` して素のスタイルへ戻す。`finished` を素で待つと二度と解決しない場合があるので `Promise.race` で頭打ち(200ms/260ms)にする。
  - この「アニメーションが進まない」挙動は show:false のE2Eハーネスで実測(`{state:'running', t:0}`)。実機では自己回復するが、待ちが解決しないと `pageSwitchBusy` が立ちっぱなしで**以後まったく切り替えられなくなる**ため、どちらにせよ必要。

**② 各ページに名前を付けて表示**

- 無地の8pxドット(`.page-dot`)を名前入りのピル(`.page-tab`)に変更。ページ数が1つでも表示する。
- クリックで切り替え / ダブルクリックでその場改名(`.page-tab-input`。Enter確定・Escape取消・blurで確定) / 右クリックで「名前を変更」「このページを削除」。
- 削除は中身(ショートカット・ウィジェット)ごと消えるので、ポップアップをもう一段出して確認する。**最後の1ページは削除不可**(メニュー項目を disabled)。
- 保存経路は新設せず既存のものを使う: ページ=startフォルダ直下のフォルダなので、改名は `bookmarks:update-item`(`updateItem` は type=folder でも title を更新する)、削除は `bookmarks:remove`(フォルダは中身ごとカスケード削除)。
- **道連れ: 既定のページ名が衝突する問題**。`addStartPage` の既定名が `ページ${枚数+1}` だったため、[ページ1・ページ2・ページ3] からページ2を消して追加すると「ページ3」が2つ並ぶ。名前を出さない仕様のうちは目立たなかったが、名前を並べる以上は致命的なので**空いている一番小さい番号**を選ぶようにした(この例なら「ページ2」)。
- 既知の割り切り: ページを削除するとブックマーク側は中身ごと消えるが、そのページのウィジェット配置(`setWidgetLayout` の保存分)は孤児として設定に残る。表示には出ないので放置。
- `scripts/stub-internal-preload.js` の `updateShortcut`/`removeShortcut` を「ページなら実データに反映して `onBookmarksState` を発火」に拡張し、E2Eでも本物と同じ再読み込み経路を通す。

**③ 横スワイプの受け口を広げる**

- wheel/touch のリスナを `#quick-links` から `document` へ。アイコンが数個だと `#quick-links` の面積がほとんど無く、スワイプがほぼ効かなかった。入力欄・ポップアップ・モーダルの上では無効(`swipeExcluded`)。

**④ リンクから開いたタブをリンク元のすぐ右へ(ホイールクリック含む)**

- `createTab` に `openerTabId` を追加し、`setWindowOpenHandler` から `tab.id` を渡す。ホイールクリック/Ctrl+クリック(disposition=background-tab)も target=_blank も同じハンドラを通る。
- **アクティブタブ基準ではなくリンク元基準**。画面分割の非アクティブ側や裏タブのスクリプトから開いた場合でも正しい位置に入る。
- 同じタブから続けて開いたときは Chrome と同じく開いた順に並ぶ(`insertIndexAfter` が、同じ opener を持つ兄弟タブの後ろまで挿入位置を送る)。素直に「リンク元の直後」に入れると 3枚開いたとき 3→2→1 の逆順になる。
- `nearActive`(ショートカット/ジェスチャー)は従来通りアクティブタブ基準。「+」ボタン・セッション復元は末尾のまま。

**⑤ 道連れ: 実機のmain未捕捉例外(ウィンドウを閉じるときの後始末)**

- `npm run start:verify` 相当の実機起動→終了で `TypeError: Cannot read properties of undefined (reading 'isDestroyed')` が出ていた。破棄の順序によっては `view.webContents` が先に消えて **undefined** になるのに、`view.webContents.isDestroyed()` / `.close()` を無条件で呼んでいた。
- 直した箇所: `tab-manager.js` の `dispose()`(タブのwc・overlay)、`side-panel.js` の `destroyWebView`/`destroyPanelView`、`media-player.js`・`timer-panel.js` の `destroy()` の計5か所。修正後は起動→終了で未捕捉例外・レンダラーエラーとも0件。

**検証**

- `npx electron scripts/test-newtab-widgets.js`(全55項目)。追加: 切り替え後の opacity/transform、ページ名の一覧表示、名前クリックでの切り替え、ダブルクリック改名、右クリック削除(確認の二段目まで)、最後の1ページの削除不可。
- `npx electron scripts/test-window-tabs.js`(全53項目)。追加: リンク元の直後に入る/続けて開いた2枚目が1枚目を押し戻さない/リンク元が非アクティブでもリンク元基準。リンクのテスト用に `/links` を返すローカルサーバーを先頭で立てる(後半のWebパネル検証と共用)。
- `npx electron scripts/test-background-tab.js`: ホイールクリックで開いたタブに `openerTabId` が載ることを追加。
- **ハーネスの注意点(次回のため)**:
  - chrome UI付きのウィンドウ(`browser.createWindow()`)では `sendInputEvent` がタブのWebContentsViewに届かない。実クリック相当の中クリックが試せるのは `test-background-tab.js` のような素の BrowserWindow + TabManager で**タブが1枚だけ**のときに限る(2枚目のViewを足した時点で届かなくなる)。並び順の検証は同じ `setWindowOpenHandler` を通る target=_blank のクリックで代替した。
  - リンク先が `data:` URL だと、Chromiumが新しいウィンドウを作る前に弾く(トップフレームのdata:遷移は禁止)。リンクのテストは実際にHTTPで配信する。
  - `capturePage()` はこの環境ではGPU有効だと `UnknownVizError` で失敗する。スクショを撮る使い捨てスクリプトでは `app.disableHardwareAcceleration()` を付ける。
