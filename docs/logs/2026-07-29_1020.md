# 2026-07-29: タブがあふれたときの見せ方(最小幅の設定・端のフェード・アクティブタブの張り付き・新規タブへの自動スクロール)

## 決定事項とWhy

ユーザー依頼「タブの最小幅を設定からかえられるようにして。また、タブが増えてきてはみだした時にはフェードアウトさするなどして続きがあることが視覚的に分かりやすくして。アクティブタブはスクロールしても隠れないように表示するようにして。新しいタブを開いた時には、そのタブが画面内に入るようにスクロールして」。

**① タブの最小幅を設定に出した**

- `tabMinWidth`(既定140px、範囲56〜200px。プロファイル単位)。設定画面「タブ」のスライダーで、つまみを動かしている間に即反映する。
- 実体はCSS変数 `--tab-min-w`。renderer が `ui:settings` で `<html>` に入れ、`.tab` と `.tab-drop-slot.open` の `min-width` が読む(挿入スロットも揃えないとドラッグ中の隙間が実際のタブとずれる)。

**② あふれている側を「フェード + 送りボタン」で示す**

- フェードは**タブ自身をマスクで消す**(`-webkit-mask-image` の linear-gradient を `#tabs` / `#group-tabs` に掛ける)。帯の色を重ねる方式にしなかったのは、ウィンドウの外観が半透明・グラデ・パターンでも成立させるため。縦タブでは向きを上下に変える。
- フェードだけだと「薄くなっただけ」で気づきにくかったので(実機のスクショで確認)、**送りボタン(‹ ›)**も足した。押すと表示幅の8割ぶん送る。
- **あふれている間はボタンの場所を空けたままにする**(`hidden`=場所ごと消す / `off`=場所は残して見せない)。押せる側が変わるたびに幅が48px動くと、直前に「ここまで送る」と決めた位置がずれて端のタブが数十px隠れる(実際にこの不具合が出た)。
- 縦タブでは送りボタンを出さない(レールにスクロールバーが出ているため)。

**③ アクティブなタブは張り付かせて隠さない**

- `position: sticky` + `left: 0; right: 0`(縦タブは `top`/`bottom`)。両端を0にすると、はみ出しそうな側の端で止まる = どちらへスクロールしても見えたまま。
- 張り付いている間だけ `.pinned` を付け、**不透明**にして影を落とす(`--tab-active` は半透明なので、不透明な `--bg` を下敷きにしてから重ねる)。下を流れるタブが透けると読めなくなるため。グループチップはグループ色を保ったまま不透明化し、2段目とつながっているチップ(`.linked`)は橋と同じ色・影なしのまま(継ぎ目に線が出るのを避ける)。
- 張り付いている側はフェードしない(掛けると張り付いたタブ自身が薄くなる)。

**④ 新しいタブ・選び直したタブを見える位置へ**

- 前回の描画のタブID一覧と比べ、増えた1枚があればそこまでスクロールする(裏で開いたタブも対象。最初の描画とセッション復元=一度に何枚も増えるときは動かさない)。
- 送り先は `scrollIntoView` では出せない。**張り付いているタブは「見えている」と判定されて動かない**ため、自前の `ensureTabVisible()` で足りない分だけ `scrollTo` する。張り付いているタブの下に隠れないよう、**張り付いている側だけ**1枚ぶん余裕を空ける。

**測定の落とし穴(重要)**: 位置の判定は要素の矩形を測るが、
- 張り付き中(sticky)の矩形は**見た目の位置**を返す → `measure-raw` クラスで一時的に `position: relative !important` にして本来の位置を測る。詳細度が足りないと効かないので `!important` が必要だった。
- 並べ替え後のFLIPアニメーション(transform)も矩形に乗る → 同じクラスで `transform: none !important`。Web Animations は `!important` の作者スタイルに勝てないので確実に止まる。**これを入れるまで、アニメーション中に走った判定で「張り付いている」と誤認したまま固まる**不具合が出ていた(スクロールイベントが来ないので直らない)。

**⑤ 検証**: `npx electron scripts/test-tab-scroll.js [スクショdir]`(38件)。最小幅の反映・あふれ始める枚数の変化、左端/途中/右端でのフェードの出方、送りボタンの出方と実際に送れること、張り付き(本来の位置は範囲外なのに見えている・不透明・その側はフェードしない)、新しいタブへの自動スクロール、縦タブ、あふれなくなったら全部戻ること。見た目はスクショではなく `getBoundingClientRect()` の実測で判定する。
