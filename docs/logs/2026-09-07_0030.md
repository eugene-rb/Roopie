# 2026-09-07: リンククリックで about:blank タブが残る不具合を修正（ユーザー報告）

## 決定事項とWhy

ユーザー報告「リンクをクリックしたときに about:blank になることがある」。切り分け（広告ブロックOFFでも発生 /
「PDFを開く」「ダウンロード」系ボタンで起きる / いろいろなサイト）から、`target="_blank"` / `window.open` で
新規タブを開く経路（`tab-manager.js` の `setWindowOpenHandler`）に **同じ症状を出す独立した原因が2つ** あった。

### 原因1: ダウンロードに化けた遷移でタブが取り残される（主因）

`setWindowOpenHandler` は `deny` + `createTab(details.url)` する。リンク先が `Content-Disposition: attachment`
などで **ダウンロードに化ける**と、Chromium はメインフレーム遷移を中断し、`will-download` でダウンロードは
処理されるが **タブは about:blank のまま残る**。実測で、この経路では新規タブの webContents に
`did-fail-load` も `did-navigate` も飛ばないことを確認（当初 `did-fail-load(-3)` で拾う設計にしたが空振り）。

**対応**: `TabManager.attachDownloadWatch()` を追加。セッションの `will-download` の第3引数（開始元 webContents）で
タブを引き当て、`closeIfStillborn` 指定かつ `!committed`（メインフレームを1度もコミットしていない）なら
`closeTab` する。Chrome/Edge と同じ。`switchSession` で張り直し、`dispose` で解除。`setWindowOpenHandler` /
side-panel / popup-window(`openInOwner`) の `createTab` 呼び出しに `closeIfStillborn: true` を付与。
外部スキーム等での即中断（`ERR_ABORTED = -3`）は `did-fail-load` 側で同じ条件で閉じる（保険）。

- `tab.committed` は `attachEvents` の既存 `did-navigate` で立てる。エラーページのコミットも含むので、
  DNS 失敗（-105）等の実エラーは従来どおりエラー表示が出てタブは残る（回帰テストで確認）。

### 原因2: URL未確定の window.open + 後から location 代入

`var w = window.open('about:blank'); w.location = url;` の遅延パターン（SNSの外部リンク・リダイレクタ・
印刷/レシートのポップアップ等で一般的）。`deny` すると `window.open()` が `null` を返し、その後の代入が
失敗して about:blank タブが残る（2026-07-27 の「deny すると window.opener が切れる」の別パターン）。

**対応**: `popup-window.isBlankTarget(details)`（`!url || url === 'about:blank'`）を追加。3つの
`setWindowOpenHandler`（tab-manager / side-panel / popup-window のネスト）で
`isPopupRequest || isBlankTarget` を見て、Google ログインのポップアップと同じく本物のウィンドウで開く
（`responseFor`。features 無しなので 800×600 中央）。後から `w.location` が入ればそのウィンドウが遷移する。

- ユーザーに方針を確認 → 「まかせる（推奨で）」。Chrome はタブで開く場面でも小ウィンドウになるトレードオフは
  受容。必要なら後で「実URL判明時にタブへ戻す」拡張を検討。
