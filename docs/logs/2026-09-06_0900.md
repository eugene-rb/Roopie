# 2026-09-06: 拡張機能のショートカットキー(chrome.commands)が効かないのを実装で補った

ユーザー報告「DarkReader のショートカットキーがきかない」。

## 根本原因

`electron-chrome-extensions`(v4.9.0)は **`chrome.commands` をほぼ実装していない**。
- ライブラリの `CommandsAPI` は `commands.getAll` しか持たず、しかも `shortcut: ""` を返すだけ。
- キー入力の監視も `chrome.commands.onCommand` の発火も一切しない。
- README の対応表でも `commands.getAll` / `commands.onCommand` の両方が未実装(`[ ]`)。

DarkReader(MV3, 4.9.130)の実際の manifest.commands:
- `toggle` → `Alt+Shift+D`(拡張全体のオン/オフ)
- `addSite` → `Alt+Shift+A`(現在のサイトのみ)
- `switchEngine` → 既定キーなし

いずれも `chrome.commands.onCommand` 経由のカスタムコマンド(`_execute_action` は使っていない)。
DarkReader の background は `chrome.commands.onCommand.addListener` を登録済みなので、
メイン側からイベントを配送すれば動く。プリロード側(`ExtensionEvent("commands.onCommand")`)は
既に本物で、`crx-add-listener` → router の listener 登録まで通っている。**足りないのはメイン側の
「キー入力を拾って listener へ配送する」部分だけ**。

**実測で確認**: 本物の Roopie ウィンドウ(`titleBarStyle:'hidden'` + `setupMenu()`)で、
タブの webContents の `before-input-event` に `Alt+Shift+D`(`code=KeyD alt=true shift=true`)が届く。
Roopie のメニューに `Alt+Shift+*` の割り当てが無いのでネイティブメニューに食われない。

## 修正(Roopie 側のみ。node_modules パッチ不要)

### `src/main/extension-commands.js`(新規)— `ExtensionCommandsAPI`
`ExtensionSupport._attach` で `ExtensionDownloadsAPI` と同様にセッション単位で生成。

- 読み込み済み拡張の `manifest.commands` の `suggested_key`(`windows`→`default`)を
  正規化したアクセラレータ表(`table`)を構築。`extension-loaded`/`extension-unloaded` で再構築。
- `attachTab(wc)`: `before-input-event` を張り、`keyDown`(オートリピート除外)で
  **`input.code`**(物理キー)+ 修飾子からアクセラレータを組み立てて `table` と照合。
  一致時のみ `event.preventDefault()` + ディスパッチ、非一致はページへ素通し。
  - `input.key` は Alt 併用時にレイアウト依存で当てにならないため `code` を基準にする
    (`KeyD`→`D`, `Digit9`→`9`, `F1`〜`F24`, `ArrowLeft`→`Left`, `Comma`→`,` 等)。
- ディスパッチ:
  - `_execute_action` / `_execute_browser_action` / `_execute_page_action`
    → `extensions.api.browserAction.activateClick({ eventType:'click', extensionId, tabId: wc.id, anchorRect })`
      でツールバーのポップアップを開く(browserAction クリックと同じ経路)。
  - それ以外の名前付きコマンド
    → `extensions.ctx.router.sendEvent(extId, 'commands.onCommand', name, tab)`。
      SW がまだ `onCommand.addListener` を済ませていないと router に listener が無く空振りするため、
      `startWorkerForScope` で起動を待って一度だけ再試行(初回空振り対策)。
- `commands.getAll` を `ctx.router.handle` で上書きし、実効ショートカットを返す
  (ライブラリの空文字のままだと DarkReader ポップアップの Hotkeys 表示が空になる。
  `router.handle` は後勝ちなので `new ElectronChromeExtensions` 後に上書きで効く)。
- キー変換・正規化(`accelFromInput` / `accelFromSuggestedKey`)は純関数として分離・エクスポート
  (`keybindings.js` の `normalizeAccel` を流用)。

### `src/main/extension-support.js`
- `commandsBySession` Map を追加。`_attach` で `ExtensionCommandsAPI` を生成。
- `addTab(wc)` から `this.commandsBySession.get(wc.session)?.attachTab(wc)` を呼ぶ。

## スコープ(意図的な線引き)

**有効範囲はページ(タブ)にフォーカスがあるときのみ**(ユーザーが選択)。
アドレスバー等 Roopie 自身の chrome にフォーカスがあるときは対象外。報告の症状
(ブラウジング中に効かない)をカバーする最小実装。将来 chrome フォーカス時も拾うなら
`window.webContents` にも `attachTab` 相当を張り、アクティブタブを tabManager 経由で解決する。

## 検証

`scripts/test-extensions-commands.js`(新規・再利用可・自己判定):
1. キー変換の単体(`accelFromInput` / `accelFromSuggestedKey` の一覧)
2. フィクスチャ MV3 拡張(commands + onCommand を storage に記録する SW)を実際に読み込み、
   実タブへ `sendInputEvent` で `Alt+Shift+D` → SW が `onCommand` を受け取る / 2連打できる
3. 一致しないキー(`Alt+Shift+K`)はページの keydown に届く、一致キーは届かない
4. `_execute_action` は `activateClick(click)` へ振り分けられる(`sendEvent` ではない)
5. `commands.getAll` が実効ショートカットを返す
6. **実アプリ配線**: `browser.js` のウィンドウでタブ生成時に `attachTab` される / そのタブから
   `Alt+Shift+D` で SW が受け取る

加えて本物の DarkReader を読み込んだ手動プローブで
`[DR SW] commands.onCommand (result) toggle` / `addSite` が出ること、フレッシュな
プロファイルでは `Alt+Shift+A` で実際にページが暗転すること(`.darkreader` style が 0→8、
背景 `#fff`→`rgb(24,26,27)`)を確認。

回帰: `test-extensions-rich.js` / `test-extensions-toolbar.js` / `test-extensions-downloads-api.js` パス。
