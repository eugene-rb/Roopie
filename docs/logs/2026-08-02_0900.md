# 2026-08-02: ウェブストア以外(サードパーティ)の拡張機能をフォルダから読み込めるようにした

## 決定事項とWhy

ユーザー依頼「サードパーティ拡張機能を読み込めるようにして」。これまでは Chrome ウェブストアの拡張機能IDを入れる導線しかなく、自作の拡張機能や GitHub などで配られている拡張機能を入れられなかった。Chrome の「パッケージ化されていない拡張機能を読み込む」に相当する導線を足した。

**① 読み込みは「コピーしてから」**

- 設定画面「拡張機能」の**「フォルダから読み込む」**でフォルダを選ぶ(`extensions:load-unpacked` → `dialog.showOpenDialog`)。選ぶのは **manifest.json のあるフォルダ**(zip配布のものは展開してから選ぶ。案内文にも書いた)。
- 選んだフォルダは**そのまま読み込まず、プロファイルの `extensions/local-<名前>-<パスのハッシュ>/` へコピーしてから読み込む**。元フォルダを消したり動かしたりしても壊れない。
- フォルダ名にパスのハッシュを入れているので、**同じフォルダを選び直すと同じ場所に入れ替わる=更新**になる。拡張機能IDはパスから決まるので変わらず、ピン留めや有効/無効の設定もそのまま引き継がれる。名前が同じでも別フォルダなら別物として並ぶ。
- 読み込み元のパスは `extensions/.roopie-local.json`(フォルダ名 → 元のパス)に控える。manifest.json が無いので拡張機能のスキャンには拾われない。設定画面の「詳細」に出す。

**② 次回起動時の読み込みはライブラリ任せ**

- `installChromeWebStore({ allowUnpackedExtensions: true })` にした。electron-chrome-web-store は `extensions/` 配下を深さ2まで探して manifest.json のあるフォルダを読み込み、**manifest に `key` があればストア、無ければ unpacked** と分類する。ストアの拡張機能は crx の展開時に `key` が入る(実機のインストール済み5件すべてで確認)ので、このフラグを立てても既存の分類は変わらない。
- そのため**独自の「起動時に読み込むパスの一覧」は持たない**。無効化(`disabledExtensions`)・ピン留め・一覧表示・再有効化はストアの拡張機能と同じ経路のまま動く。

**③ MV3のバックグラウンド(service worker)が起動していなかった**

- `loadExtension()` の直後に `startWorkerForScope()` を呼んでも**必ず失敗する**(登録がまだ済んでいない。300ms ほど待てば成功する = 実測)。electron-chrome-web-store の `loadAllExtensions` も即座に呼んでいるので、**起動時に読み込んだストアの拡張機能でも同じく失敗していた**(`Failed to start worker for extension ...`)。
- 200ms間隔で5回まで起こし直す `startWorker()` を入れ、フォルダからの読み込み・再有効化・起動時の一括読み込みの3か所で使う。Chromium側でも遅れて自動起動するので、最後まで失敗しても致命傷ではない。

**④ 削除の分岐**

- `uninstallExtension()` は `extensions/<拡張機能ID>/` を消す実装なので、フォルダから読み込んだもの(=ID名のフォルダではない)には効かない。読み込み解除 + コピー先フォルダの削除 + 控えの削除に分けた。

**⑤ そのほか**

- シークレットウィンドウからは読み込めない(拡張機能を取り付けていないので、使用中のプロファイルへ勝手に入ってしまう)。IPC側で弾いてエラーを返す。
- **入れ直し・削除のときは `disabledExtensions` からIDを外す**(`forgetDisabled`)。拡張機能IDは入れ直しても変わらないので、無効にしたまま入れ直すと「その場では動くのに次の起動でまた外れる」ことになる。インストール(ストア)・フォルダからの読み込み・削除の3か所で外す。
- manifest.json が無い/JSONが壊れている/name・versionが無いフォルダは**コピーする前に**理由付きで失敗させる。読み込みに失敗したらコピーも消す(読めないものを残さない)。
- 一覧に「フォルダから読み込み」バッジ(`.ext-badge`)、詳細に「読み込み元」を追加。
- 検証: `npx electron scripts/test-extensions-unpacked.js`(コピー・再起動時の自動読み込み・更新・無効化・失敗の扱い・削除・service workerの起動)/ `npx electron scripts/test-extensions-unpacked-ui.js [スクショdir]`(設定画面の見え方)。既存の `test-extensions-rich.js` / `test-extensions-toolbar.js` / `test-extensions-menu.js` も通ることを確認。
- 未対応: **.crx / .zip をそのまま選ぶことはできない**(展開してからフォルダを選ぶ運用)。

**⑥ ついでに依存の脆弱性(high 2件)を消した**

- `fast-uri`(electron-builder → ajv 経由。開発時のみ)は `npm audit fix` で 3.1.3 → 3.1.5。
- `adm-zip`(electron-chrome-web-store が crx の展開に使う。**配布物に入る**)は 0.5.18 で「細工したZIPで4GBのメモリ確保」。electron-chrome-web-store は最新の 0.13.0 でも `^0.5.16` のままなので、**`package.json` の `overrides` で `adm-zip: ^0.6.0` に固定**した(Dependabotの案内も「overrideを入れろ」)。`npm audit` は 0 件になった。
- 0.6.0 で壊れていないことを実際に確かめた: 使っているのは `new AdmZip(buffer)` と `extractAllTo(dest, true)` の2つだけで、**ウェブストアからの実インストール**(crxのダウンロード → 展開 → 読み込み → 削除)が通る。検証: `npx electron scripts/test-extension-install.js [拡張機能ID]`(**ネットワークが必要**)。
- `npx electron-builder --win --dir` でパッケージまで通ること、`app.asar` の中の adm-zip が 0.6.0 になっていることも確認した。
