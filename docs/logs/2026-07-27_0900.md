# 2026-07-27: タイマーの「シャットダウン」が実行されないバグを修正

## 決定事項とWhy

ユーザー報告「シャットダウンが機能してない」(23:45のアラーム+シャットダウン。2晩連続で落ちなかった)。

**切り分け**(実機の証跡から。推測ではなく順に潰した)
- `%APPDATA%\Roopie\profiles\<id>\timers.json`: 対象タイマーは `shutdown: true / shutdownConfirmed: true`、`lastFiredAt` は当夜23:45 → **発火はしている**。`status` は `running`(次回=翌日)まで戻っている → **猶予(grace)は決着済み**
- Windowsシステムログ: 当夜23:45に **イベント1074(shutdown.exe起動)が無い** → OSへコマンドが届いていない
- Node単体 / **Electronメインプロセス**の両方から `spawn('shutdown', […], {detached, stdio:'ignore'})` を実測(`/t 600` で予約 → `shutdown /a` で中止 → 1074を確認)。どちらも成功 → **spawnの仕組みは正常**
- 実行中のRoopieは `C:\Program Files\Roopie`(親プロセスは explorer.exe)、`ROOPIE_TIMER_SHUTDOWN_DRYRUN` はUser/Machine環境変数とも未設定 → **dry-runガードでもない**
- 残るのは「猶予が満了前に取り消された」だけ。コードを追うと **`fire()` の `changed()` は `onFire`(=猶予登録)より前**に走るため、`present()` が返す `fireId`/`graceEndsAt` が画面へ一度も届かない。結果フローティングパネルの行は「時間です」表示のままで、✕ボタンは `cancelTimerFire` ではなく **`acknowledgeTimer` に落ちる**(timerpanel.js の `t.fireId ? cancel : acknowledge`)。`acknowledge()` は猶予を消して決着させるので、**✕を押した時点でシャットダウンが黙って取り消されていた**

**変更**
- `timers.js`: `registerGrace()` の最後で `onChange?.()`(猶予は永続対象外なので保存はしない)。これで「あと15秒」が出て✕が `cancelFire` になる。`acknowledge()` は危険アクションの猶予がある間は何もしない(`hasDangerousGrace()`)= 取り消しは fireId 付きの `cancelFire` だけに限定
- `timer-actions.js`: 実行ログ+`error`/終了コードの記録を追加(空振りを黙らせない)。失敗時だけ `<userData>/timer-shutdown-errors.log` へ追記する(無人・ターミナル無しで走るためconsoleでは証拠が残らない)。dry-runガードは `process.defaultApp`(開発時)だけ有効にし、製品版では環境変数を引き継いでも無効化されないようにした
- コマンドは `/s /t 0` のまま(`/f` は検討したが不採用。他アプリの未保存データを捨てる副作用があり、イベントログ上は07/23〜07/25に `/s /t 0` で3回成功していて中断された実例が無い)
- `browser.js`: 猶予満了時の実行順を「シャットダウン → ウィンドウを閉じる」へ(最後のウィンドウを閉じてアプリ終了処理に入る途中でコマンドを投げないため)

**検証** — `npx electron scripts/test-timer.js`(26項目すべてOK。猶予のfireId/graceEndsAtが一覧に載る・acknowledgeでは猶予を消さない・dry-runガードの3項目を追加)。新規 `scripts/test-shutdown-spawn.js` はメインプロセスからのシャットダウン予約がOSへ届くかを実機を落とさず確認する(`/t 600` → `/a`)。
