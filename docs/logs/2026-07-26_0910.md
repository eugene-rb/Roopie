# 2026-07-26: ツールバーの拡張機能ボタンが出ないバグ

## 決定事項とWhy

ユーザー報告「ツールバーの拡張機能管理アイコンが表示されない」。

**原因: 起動時の一覧配信が、拡張機能の読み込み完了より先に走っていた**

- パズルボタン(`#extensions-menu-btn`)は `extensions:state` で受け取った件数が1件以上のときだけ出す。この状態を送るのは①ウィンドウの初期状態送信(`sendAllTo` = `did-finish-load`)②インストール/削除/有効無効の切り替え、の2経路だけ。
- 拡張機能の読み込み(`ExtensionSupport#attach` → `installChromeWebStore`)はディスクI/Oの非同期処理で、`createWindow` から投げっぱなしにしていた。**完了後に配り直す経路が無い**ため、初期状態送信に間に合わないと空の一覧が届いたきり更新されず、ボタンは一生 `hidden` のまま。
- 実機の拡張4つをコピーした一時プロファイルで計測して確定: `did-finish-load`(初期状態送信)が **1322ms・一覧0件**、`attach` 完了が **1452ms・4件**。拡張が1つだけの軽い環境では読み込みが先に終わるため再現しない = 「出るときと出ないときがある」ように見えていた。

**修正**

- `browser.js`: `attach()` の完了後に `browser.sendExtensionsFor(profile.id)` で配り直す(`broadcastProfile` なので同じプロファイルの全ウィンドウに届く)。
- `extension-support.js`: `attach()` を**取り付け中のPromiseを共有する**形に変更(`this.attaching`)。従来は `bySession.has()` で即 return していたため、1枚目の読み込み中に開いた2枚目のウィンドウや `install()` が「まだ読み込めていない状態」で先へ進んでいた。本体は `_attach()` へ移動。

**検証** — `scripts/test-extensions-toolbar.js` に起動時のケースを追加

- 実物と同じ配置(`profiles/<id>/extensions/<拡張ID>/<version>_0/`)で拡張を仕込んでから `createWindow` する。**ローダーは `manifest.key` を持つものだけ「インストール済み」として読み込む**(key無しは unpacked 扱いで `allowUnpacked` が必要)ため、フィクスチャにはRSA公開鍵(DER/base64)を持たせる。
- 順序を必ず再現するため、**起動時の1回だけ** `session.extensions.loadExtension` を遅らせる。`attach()` 全体を遅らせると `ElectronChromeExtensions` の生成まで後ろへずれて `crx-msg-remote` が総崩れになり、実機と違う状況になる(遅れるのは読み込みだけ)。
- 修正を戻すと「起動時: 保存済み拡張があればパズルボタンが出る」だけが落ちることを確認済み。
