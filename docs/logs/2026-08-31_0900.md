# 2026-08-31: DarkReader等のピン留め拡張のポップアップが画面外に出るのを修正 / タブバー空き領域へのD&Dを直す

ユーザー報告2件。独立しているのでコミットも分ける想定。

## ① ピン留めした拡張のフローティングUI(ポップアップ)が「うまく見えない」

**症状**: DarkReader のようにポップアップの背が高い拡張をツールバーにピン留めすると、
アイコンをクリックしても中身がほぼ見えない。

**原因**: `renderer.js` の `renderExtensionActions()` で `<browser-action-list>` に
`alignment="top right"` を付けていた。electron-chrome-extensions の `PopupView.updatePosition()`
は alignment 文字列に:
- `"top"` を含む → ポップアップを**アイコンの上**に出す(`y = winTop - popupHeight + anchorY - 5`)
- `"right"` を含む → 左端をアイコン左端に揃える(=**右へ伸びる**)

を行う。ツールバーは画面上端・アイコンは右寄りなので両方とも逆向き。しかも画面外clampが
無いので、上に出たポップアップはウィンドウの外へ突き抜ける。README の例が
`alignment="top right"` なのでそれを真似たのが事故の元。

**実測**(`test-extensions-toolbar.js` のフィクスチャ拡張): 修正前はポップアップ `y:70` に対し
ウィンドウ `y:116` = 上端より46px上。背の高い DarkReader なら数百px上=ほぼ全部画面外。

**修正**: `alignment` を `'bottom left'`(= 下・アイコン右端揃え。Chrome/Edge と同じ)に。
1行 + 罠を説明するコメント。修正後 `y:198`(アイコン直下)、右端はみ出しも無し。

**検証**: `scripts/test-extensions-toolbar.js` に「ピン留めアイコンのクリックでポップアップが開く」
「アイコンより下に出る」「ウィンドウ上端の内側」「左右端をはみ出さない」を追加
(`browser-action-popup-created` イベントで PopupView を掴んで `browserWindow.getBounds()` を実測)。
修正前は2件NG → 修正後は全項目パス。

画面外clamp(`will-move`/`will-resize` の payload を書き換える方法)は**入れていない**:
サードパーティ dist の "emit がオブジェクト参照を渡し、spread はその後" という細かい挙動に
依存し、更新で無言で壊れる。alignment 修正だけで通常のウィンドウ配置では収まる。

## ② リンク/ブックマーク/テキストをタブバーの**空き領域**に落としても反応しない

タブの上(`#tabs`。常時 no-drag)ではテキスト検索ドロップが効くのに、タブの無い空き領域
(`#tab-bar` の `-webkit-app-region: drag` 部分)だけ死ぬ、という報告。

**しくみ**: `#tab-bar` の空き領域はウィンドウ移動用のドラッグ領域。ドラッグ中だけ
`dnd-armed` クラスで `no-drag` に切り替えて落とせるようにする作り。

**原因(推定・下記の通り未確定)**: 武装/解除のライフサイクルが自滅していた。
- 武装は `document` の `dragover` で `text/plain` があるときだけ
- 解除が `dragleave` かつ `relatedTarget` 無しのとき

ポインタが「まだ `no-drag` に切り替わっていない空き領域」に乗ると、そこはイベントを出さない
ドラッグ領域なので `dragleave`(relatedTarget無し)が誤発火する → **武装 → 空き領域へ入る →
即解除 → 空き領域が永久に落とせない**、というループ。`#tabs` の上は常時 no-drag なので
この罠に掛からず、テキストドロップが効く = 報告の症状と一致。

**修正**(`renderer.js`):
- 武装は種類を問わず `dragenter` / `dragover` で(ページからのリンク/テキストがクロームへ
  入ってくる最速の合図が `dragenter`。空き領域へ直接入るケースに間に合わせる)
- `dragleave` での解除を撤去
- 解除は `drop` / `dragend` と、ドラッグ後に通常のマウス操作(`mousemove` / `mouseover` /
  `click`)が戻ってきた時。HTML5ドラッグ中はこれらが飛ばないので「終わった」の安全な合図。
  武装が残ってウィンドウ移動を潰すのも防ぐ。
- `dragMode()` / ドロップで `text/uri-list` も受ける(ページ内リンクは `text/plain` を
  持たないことがある)。取り出しは `dropText()`(plain→uri-list の順。`#` 行はコメントなので飛ばす)。
- `cleanupDrag()` も同じ `disarmDnd()` 経路に。

**検証**: `scripts/test-tab-drop-url.js` に武装状態機械の合成イベントテストを追加
(「リンクのドラッグでクロームに入ると武装」「途中の dragleave では武装を外さない」
「後で mousemove すると外れる」「uri-list だけのリンクでもドロップでタブが増え、検索を
経由せずそのURLで開く」)。あわせて起動直後の初期タブ待ちを固定1500ms → ポーリングにして
セクション2のflaky(数のずれ)を潰した。

**⚠️ 未確定 / 次にやること**:
合成 `DragEvent` は要素IDに直接dispatchするので `-webkit-app-region` のOSヒットテストを
通らない = **「空き領域が実際に落とせるようになったか」はこのテストでは検証できていない**。
「Windows でドラッグ中に `-webkit-app-region` の再評価が効くか」は手動ドラッグでしか
確認できない。**要手動確認**: ページのリンクをタブバーの空き領域(タブの右)へドラッグ →
バーが青くハイライトされ、新タブが開くか。

これでも空き領域が落とせない場合、残る原因は「ドラッグ中に app-region が再評価されない」。
その時の**フォールバック**: `+` ボタンの右に**常時 `no-drag`** のドロップ受け皿要素
(`flex:1`、末尾挿入のドロップ先)を置く。トレードオフ = その帯からのウィンドウ移動
(ダブルクリック最大化含む)は失う。`#tabs` を `flex:1` にする案は `+` ボタンが最右へ
飛ぶので却下(advisor指摘)。
