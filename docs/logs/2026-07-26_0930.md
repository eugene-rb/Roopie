# 2026-07-26: マウスジェスチャーの検出をメインプロセスへ(重いページでも効くように)

## 決定事項とWhy

ユーザー報告「コンテンツが重くてしばらくマウスジェスチャーが使えないことがある」。

**原因** — 検出が `gesture-preload.js`(= レンダラーのメインスレッド)にあった。ページのJSが重いと preload の mousedown/mousemove も同じスレッドで止まる。DOM入力をワーカーへ逃がす手段はないので、検出そのものをメインプロセスへ移すしかない。

**実測**(`scripts/test-gesture-input.js` の手動パート。ページを8秒間ビジーループで固め、実マウスで右ドラッグ)
- メイン側の `webContents 'input-event'`: mouseDown / mouseMove 100件超 / mouseUp をすべて受け取り、パターンも確定できる
- ページ側: 固まっている間は0件。解除後にまとめて26件(coalesce済み)が届くだけ
- `contextmenu` も解除後にまとめて発火する(数秒遅れ) → **時間ベースのメニュー抑止は成立しない**
- 合成イベント(`sendInputEvent`)ではこの確認はできない。メイン側で作ったイベントがメイン側の見張りに届くのは当たり前で、「OSからの実入力がレンダラー停止中もメインへ届くか」の証明にならないため

**変更**
- 新規 `src/main/gesture-input.js`。`app.on('web-contents-created')` で全WebContentsに `input-event` を張り、**押された時点で**「対象セッションか」「除外URL(`roopie://menu` / `devtools://`)か」「ジェスチャーが有効か」を判定する。見張りを付ける時点で絞らないのは、`registerPagePreloads` がウィンドウ生成の**後**に走るためウィンドウ本体を取りこぼすから。設定(enabled/mappings)はイベント時に `windows.contextFor` → プロファイルの束から引く(プロファイル切り替えでStoreが差し替わるため、張った時点で抱え込まない)
- `ipc.js`: `gestures:perform` のswitch本体を `performGesture(wc, action)` として名前を付け、`browser.performGesture` に載せて gesture-input から呼べるようにした(`browser.store` と同じ受け渡し方。ipc.js は require の下流なので逆にrequireできない)。IPCチャンネル自体は残している
- `gesture-preload.js` は検出をやめ、①軌跡とラベルの描画(メインから `gestures:trail` で座標を受ける。座標はページズームで割ってから送る)②スクロール系アクションの実行 ③右クリックメニューの抑止 の3つに縮小。設定(`gestures:config`)を持つ必要がなくなった(ラベル文字列はメイン側で組み立てる)
- **メニュー抑止は preload だけで完結させる**(自分が受け取った mousedown→mouseup の最大移動量だけで判断)。メインから「抑止して」と送る方式は、重いページでは contextmenu が数秒遅れて発火する一方でIPCは別経路を先に届くため、順序を当てにできない。preload方式なら入力キューの順序(mousedown → mousemove → mouseup → contextmenu)がそのまま保たれるので、遅れても正しく抑止される。往復ジェスチャー(→←など)は終点が始点に近いので、途中の**最大**距離で見る

**残る制約** — 軌跡の描画とスクロール系アクション(scrollTop/Bottom/PageUp/PageDown)はページのメインスレッドでしか実行できないため、重いページでは遅れる。ジェスチャーの成立とそれ以外のアクション(タブを閉じる・戻る等)はメイン側で完結する。

**検証** — 新規 `scripts/test-gesture-input.js`(重いページは `scripts/test-heavy-page.html`。単体配信は `node scripts/serve-test-page.js test-heavy-page.html 8947`)。`require.cache` に偽の browser.js を差し込んでブラウザ本体を起動せずに検出部だけを回す。自動11項目(アクション実行 / 分割ペインで操作した側に効く / 多方向パターン / 小さな移動は無視 / 軌跡とラベル / スクロール)+ 手動(実マウス): 8秒フリーズ中でもジェスチャーが成立、ジェスチャー後はメニューが出ず、単なる右クリックでは毎回出る。
**注意** — 検証ウィンドウが背面に回るとレンダラーがスロットルされ、スムーススクロールが進まない(実装ではなく検証環境の問題)。Viewに `backgroundThrottling: false` を入れて回避している。
