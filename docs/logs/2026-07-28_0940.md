# 2026-07-28: タブが増えたときのホイールスクロール(横タブ/縦タブ両方)

## 決定事項とWhy

ユーザー依頼「タブが多くなりすぎた場合ホイールでスクロールできるようにして。(縦横どちらも)タブの内容が判別しやすいことを優先して」。

- **元の挙動**: `#tabs` は `overflow: hidden`、`.tab` は `min-width: 60px`。タブが増えると60pxまで潰れ(favicon+1文字程度)、それを超えた分は**クリップされて到達不能**だった

- 横タブ
  - `#tabs` … `overflow-x: auto` + `overflow-y: hidden` + **`min-width: 0`**(フレックスアイテムの既定の最小サイズ=min-contentに引っかかると縮まずスクロールが始まらない)
  - `.tab` … `min-width: 60px` → **`140px`**。ここまでで止めて、あふれた分はスクロールで見せる(実測でタイトル幅80px=8文字ぶん残る)。依頼の「判別しやすさ優先」をこの値で表現している
  - `.tab-drop-slot.open` の `min-width` も140pxに合わせる(隙間の大きさが実タブと違うと挿入位置がずれて見える)
  - `#new-tab-btn` に `flex-shrink: 0`(あふれても「+」は右端に残す)
  - スクロールバーは**隠す**(バーの高さが40pxしかなく、出すとタブが潰れる)。代わりにアクティブなタブを自動で見える位置へ寄せる
  - **横タブでは縦ホイールが効かない**(`overflow-x` の要素にブラウザは縦ホイールを流さない)ため `renderer.js` に wheel ハンドラを追加。`deltaX` の指定があればそちらを優先(トラックパッドの横スワイプ)、`deltaMode` が行/ページ指定でも同じ距離感になるよう換算

- 縦タブ
  - `#tabs` は元から `overflow-y: auto` だったが**スクロールしていなかった**。原因は `.tab { flex-shrink: 1 }` が**縦並びでは「高さ」に効く**こと。タブが上下に潰れてあふれないため、スクロール領域が生まれない。`.chrome-body.vertical-tabs .tab { flex-shrink: 0 }` で高さを固定して解決
  - 縦は素のホイールで動くので wheel ハンドラは横タブ限定にしてある
  - レールは幅に余裕があるので細いつまみ(6px)だけ出す

- アクティブタブの自動追従
  - `renderTabs()` の最後で `scrollIntoView({ block: 'nearest', inline: 'nearest' })`。ただし**アクティブが変わったときだけ**(`scrolledActiveTabId` で覚える)。毎回やると、別のタブを探して手でスクロールしている最中に引き戻してしまう(検証項目にしてある)

- ドラッグ中の端での自動スクロール(追加依頼)
  - スクロールしていると画面外のタブの間へは落とせないので、カーソルを端(56px以内)に寄せている間だけ流す。端に近いほど速い(最大16px/フレーム)
  - **dragover はカーソルが静止すると飛んでこない**ので、最後のカーソル位置を覚えて `requestAnimationFrame` で回す
  - 流れた分だけタブがカーソルの下を通るため、スクロールするたびに挿入位置のプレビュー(スロット)も引き直す
  - 縦タブでは上下方向。並べ替え(自タブ)とページからの選択テキストのドロップ検索の両方で効く
  - 止める経路は `cleanupDrag()`(dragend)・タブバーの dragleave/drop・document の drop/dragleave(ウィンドウ外へ出た)の全部に入れる

- 検証: `scripts/test-tab-audio-effect.js` に15項目追加(全98項目OK・3回連続で安定)。タブが140pxより細くならないこと、あふれがスクロール領域になること、`sendInputEvent` の `mouseWheel` で実際に `scrollLeft`/`scrollTop` が動くこと、選んだタブが見える位置に寄ること、手動スクロール位置が再描画で戻らないこと、ドラッグで端に寄せると流れる/離すと止まる/逆端で戻ること、縦タブでも同じこと(レールはウィンドウ高さいっぱいなので `setSize(1000, 400)` であふれさせる)
  - **ドラッグの検証方法**: 実OSのドラッグは `sendInputEvent` では起こせないので、`new DragEvent('dragover', { dataTransfer, clientX, clientY })` を組み立てて `#tab-bar` へ投げる(ハンドラが見るのは `dataTransfer.types` と座標だけなので経路は通る)
  - **不安定になる条件**: 自動スクロールは rAF で回すため、ウィンドウが完全に隠れて合成が止まるとrAFが来ず落ちる(スクショの "display surface not available" と同じ状況)。失敗詳細に「rAFが動く」を出してある
- **ハーネスの注意**: 全エフェクトを並べた確認用グリッドは**クロームUI側**に描く。タブ(WebContentsView)の `capturePage` はこの環境では "Current display surface not available for capture" で失敗することがあり、`disableHardwareAcceleration()` でも直らない。またそのとき `document.body` の `data-audio-effect` を**一時的に外す**(子孫結合子なのでbody側の指定が全セルに効き、後ろに書かれたルール=ニャンキャットが全部に出てしまう)
