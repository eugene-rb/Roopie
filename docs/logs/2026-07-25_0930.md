# 2026-07-25: 新しいタブの位置 / 閉じたタブのウィンドウ間共有 / ウィンドウを閉じても音が止まらないバグ

## 決定事項とWhy

ユーザー依頼3件。

**① ショートカット・マウスジェスチャーの新しいタブをアクティブタブのすぐ右へ**

- `TabManager#createTab` に `nearActive` オプションを追加。true のときだけ `this.tabs.push(tab)` の代わりにアクティブタブの直後へ `splice`(アクティブタブが無ければ末尾)。`activeTabId` が動くのは末尾の `switchTab(id)` なので、挿入位置の計算はタブ登録前で問題ない。
- 付けた側: `menu.js`(新しいタブ Ctrl+T / 履歴 / ダウンロード / ブックマーク管理 / 設定 — いずれもアクセラレータ付き)、`ipc.js` の `gestures:perform` の `open()` ヘルパ(`newTab`・`home`・履歴/ダウンロード/ブックマーク/設定を開くジェスチャー)。
- 付けなかった側(意図的): 「+」ボタンと内部ページからの `tabs:new`(Vivaldiでも末尾)、リンクの `setWindowOpenHandler`(Ctrl+クリック/ホイールクリック)、`duplicateTab`、セッション復元、`reopenClosedTab`(記録した元の位置へ戻す)。

**② 別ウィンドウで閉じたタブも復元できるように**

- `closedTabs`(`{ url, index }` の配列)は TabManager インスタンスごとの持ち物で、閉じたウィンドウ・別ウィンドウのタブは戻せなかった。プロファイル単位の束(`browser.bundleFor()`)へ移し、`new TabManager(window, { ..., closedTabs })` で同じ配列を全ウィンドウに渡す(メモリのみ。再起動では消える=従来どおり)。
- シークレットは `closedTabs: []`(そのウィンドウ限りの新しい配列)。通常ウィンドウの Ctrl+Shift+T でシークレットのURLが出てこないことを検証で確認。
- 全ウィンドウで1本を共有するので `MAX_CLOSED_TABS` を 10 → 25 に。
- `switchSession()`(プロファイル切り替え。現状は本体から未使用でテストのみ)の `this.closedTabs = []` は共有配列からの切り離しになるため、復活させるときは切り替え先の配列を渡し直すようコメントを残した。

**③ 2枚目以降のウィンドウを閉じても音が鳴り続ける**

- 原因: `WebContentsView` の webContents は BrowserWindow を破棄しても一緒には消えない。タブを閉じる経路(`closeTab`)でしか `webContents.close()` していなかったため、ウィンドウごと閉じるとタブは生きたまま再生を続けていた。最後の1枚はアプリ終了で消えるので、**2枚目以降でだけ**表面化していた。
- `TabManager#dispose()` を新設(全タブの `setBookmarkHint(false)` / `stopMediaWatch` / `webContents.close()`、仕切り・オーバーレイの破棄、全画面ポーリングの停止)。`browser.js` の `window.on('closed')` から `tabManager.dispose()` + `sidePanel.destroyWebView()/destroyPanelView()` + `mediaPlayer.destroy()` + `timerPanel.destroy()` を呼ぶ(Webパネルやミニプレイヤーも音源になり得る)。
- **`closeTab()` のループにはしない**: ②で共有化した閉じたタブ履歴を1ウィンドウ分のタブで埋めてしまうし、最後の1枚を閉じた時点で `window.close()` を呼び返す・破棄済みレンダラーへ `sendState()` する。
- ウィンドウ破棄後は `window.contentView` に触れると例外になるため、`destroySplitDivider` / `destroyWebView` / `destroyPanelView` / `MediaPlayer.destroy` / `TimerPanel.destroy` の `removeChildView` を `window.isDestroyed()` で守った。
- タブの切り離し・ウィンドウ間移動は `releaseTab` の時点で `this.tabs` から外れるので、`dispose()` に巻き込まれない(`test-tab-detach.js` / `test-tab-cross-window.js` で確認)。

**検証**: 新規 `scripts/test-window-tabs.js`(48項目)。①は `createTab` の挿入位置と `gestures:perform` / `tabs:new` の実IPC、②はウィンドウをまたいだ復元とシークレット非共有、③は AudioContext で実際に鳴らして `isCurrentlyAudible()` を確認 → ウィンドウを閉じる → webContents が破棄されることまで見る(タブに加えて**Webパネル**も鳴らし、サイドパネル本体・ミニプレイヤー・タイマーパネルのViewまで破棄されることを確認=追加した `window.isDestroyed()` ガードもここで通る)。修正を無効化して走らせると③の3項目だけが落ちることも確認した(回帰テストとして機能している)。④はウィンドウを閉じる→記録の中身→別ウィンドウのショートカットで復元(位置・大きさ・タブ構成)→閉じ直しても再び戻せる→タブの履歴と混ざっても閉じた順の逆に戻る、まで確認。②③④とも**別プロファイル・シークレットに混ざらない**ことも見ている。既存の `test-gesture-actions.js` / `test-tab-detach.js` / `test-tab-cross-window.js` / `test-session-restore.js` は変更なしで通る。`test-background-tab.js` の「ホイールクリックでタブが増える」は**この変更の前から**失敗する(クリーンなmasterでも再現。溜まったelectronプロセスを掃除した後でも同じなので競合ではない。ハーネスの中クリック(`sendInputEvent`)が `setWindowOpenHandler` まで届いていない疑い。別途調査)。

**④ ウィンドウ単位の復元(追加依頼)**

③の直後にユーザーから「ウィンドウ単位の復元も実装して」。②の共有履歴を**タブとウィンドウが混在するLIFO**に拡張した(Chromeと同じで、Ctrl+Shift+Tは「最後に閉じたもの」から順に戻す)。

- エントリは `{ type: 'tab', url, index }` と `{ type: 'window', tabs, bounds, maximized }` の2種類。上限25件は共通。
- 記録: `browser.js` の `window.on('close')`(破棄前=タブが生きているうちに)で `tabManager.rememberClosedWindow(window.getNormalBounds(), window.isMaximized())`。**タブ1枚ずつではなくウィンドウ1件**として積む。新しいタブページ/空タブしか無いウィンドウは積まない。シークレットは対象外。
- 復元: `reopenClosedTab()` が window エントリを引いたら `onReopenWindow`(browser.js が `createWindow({ profileId, restoreTabs: entry.tabs, bounds })`+必要なら `maximize()`)。TabManagerからウィンドウは作れないのでコールバック経由。ハンドラが無い場合(単体テスト等)はそのウィンドウにタブとして戻すフォールバック付き。
- `createWindow` に `bounds` オプションを新設。既存の `x`/`y` は**カーソル座標**(タブ切り離し用に -100/-20 ずらす)なので、そのままの位置に開く用途には使えなかった。当時のモニタが外されていても見えなくならないよう、`clampToScreen()`(`screen.getDisplayMatching` のいちばん近いモニタの作業領域へ収める)を通す。
- 復元時、記録から新しいタブページを省いた結果アクティブなタブが消えることがあるので、記録側で必ず1枚 `active` を立て、`restoreTabs()` 側にも「1枚も選ばれていなければ先頭を選ぶ」保険を入れた。
- **道連れで見つけた既存バグ**: `snapshotTabs()` が `wc.getURL()`/`getTitle()` をそのまま使っており、**休止中(未読み込み)のタブが空URLとして記録されて消えていた**。セッション復元(`session-tabs`)も同じ経路なので、「復元→そのタブを開かないまま終了」でタブが失われる状態だった。`tabUrl(tab)`(hibernatedUrl込み)と `hibernatedTitle` で補うよう修正。
- 表示名も「閉じたタブを再度開く」→「**閉じたタブ/ウィンドウを再度開く**」に統一(メニュー・ショートカット設定・ジェスチャー設定。IDは `reopenTab` のまま)。
